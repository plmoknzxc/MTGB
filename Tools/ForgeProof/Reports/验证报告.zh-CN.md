# Forge ↔ Unity 验证报告

日期：2026-09-15。结论：**本次限定的真实规则交互链可行，Play Mode、Windows Player 均通过。**

这不是全卡、正式联机或完整迁移的验收。

## 环境与版本

- Windows 11，Unity 6000.3.22f1，Windows x64 Mono Development Player。
- Oracle JDK 17.0.12，Maven 3.9.16。
- Forge 提交：`746455d75515daabec62971e0544cf19c66356b3`。
- 通过编译的上游模块：forge-core、forge-game、forge-ai、forge-gui；没有创建 AI 玩家。
- 原有 MTGB 源码与内容未修改。验证工程位于 `Tools/ForgeProof/UnityProject`。

## 实际经过的规则链

两名真人控制席位 → 先手确认 → 双方保留起手 → 第一回合 MAIN1 → 打出山脉 → 通过其法术力异能产红 → 施放官方闪电击 → Forge `InputSelectTargets` 选择玩家 2 → `InputPayManaOfCostPayment` 消耗法术力池中的红色 → 堆叠出现咒语 → 玩家 1、玩家 2 分别让过 → Forge 结算。

最终断言：玩家 1 生命 20；玩家 2 生命 17；山脉横置；红色法术力为 0；闪电击位于坟墓场；堆叠为空。桥接没有调用修改生命或直接结算咒语的替代实现。

测试夹具在第一回合开始钩子内将一张山脉换成牌库里的闪电击，保持七张手牌；之后全部操作走真人输入路径。完整测试不是随机开局统计，也不检验调度规则的所有分支。

### 测量数据

峰值是每 100ms 采样的进程驻留内存，不是堆大小或严格瞬时峰值。启动时间包含资源初始化，截止第一个玩家请求。单轮耗时包含测试驱动器的主动等待。

| 环境 | 首次请求 | 单轮完整验证 | JVM 驻留峰值 | Unity 驻留峰值 | 输入确认往返中位数 |
|---|---:|---:|---:|---:|---:|
| Play Mode，3 轮 | 6.78～7.04 秒 | 14.59～14.89 秒 | 581～624 MiB | 约 380 MiB | 16.64 ms |

## 实际遇到并处理的问题

1. Forge 的规则工作线程是后台线程，主入口返回后 JVM 会退出。桥接增加显式生命周期等待。
2. 输入已进入队列时，界面提示可能尚未初始化。桥接只在对应输入提示准备好后发布候选。
3. 上游 Maven 产物的父版本含 `${revision}`，单独依赖安装产物解析失败。构建脚本在同一 reactor 中生成模块和运行依赖，然后编译桥接。
4. Unity 的 `Process.WorkingSet64` 在此环境返回 0；改用 Windows 内存接口。Oracle javapath 又是启动器而非实际 JVM，随后改为解析 `java.home` 并直接启动 JVM。最终报告已排除前两次错误内存测量。
5. 隐藏 Windows 窗口不产出截图，且帧数不代表正常呈现帧率；另外运行可见窗口确认面板并保存截图。
6. 隔离 Unity 工程启动时出现编辑器 Search 索引的 `ArgumentOutOfRangeException`；不在验证脚本中，未阻止编译、Play Mode 或构建。隐藏窗口日志另有 Graphics Ring Buffer 提示。可见窗口验证正常；没有将这些日志当作规则错误掩盖。

## 仍未证明的内容

- 正式 MTGB 卡牌数据模型、组卡、牌组印刷映射、大厅、BO3、网络同步与重连尚未接入。
- 只实现本测试必要的输入类型及闪电击玩家目标候选；其他机制仍需要适配。不是将 Forge 全部真人接口自动映射成了 Unity 协议。
- 本机测试宿主同时持有两份席位视图，便于模拟两人；正式联机必须逐连接分发。面朝下、临时查看、多人及复杂隐藏信息未验证。
- 调试按钮与自动驱动共用输入方法，但本次未执行真人逐按钮点击验收。
- JVM 每次加载固定上游资源，单进程已用约 0.6 GiB 驻留内存；每房间独立进程的生产成本需要另测，不能将此原型当作多房间容量结论。
- Player 仍依赖本机 JDK 和工作目录资源，尚未制作带 JRE 的分发包。
