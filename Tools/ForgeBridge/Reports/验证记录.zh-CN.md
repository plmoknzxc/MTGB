## 本轮修复的实际问题

- 认输由服务器自行递增请求编号，导致下一局首个客户端请求被拒绝；改为客户端统一编号。
- 自动重连重建网络对象后仍沿用旧的回调注册标记，导致不发送身份验证；改为随网络对象重新注册。
- 匿名的弃牌选择类未被识别；按基类判断并保留可读的请求类型。
- 费用选择切换到能力对话框时存在旧请求竞争；拒绝过期响应并重新发布当前选择，不计败局。

## 验证边界

BO3 自动化使用认输结束每局。以上结果不代表完整正式战场、全部卡牌效果或复杂隐藏机制可玩。排序、多选、揭示及控制其他玩家等未适配交互仍明确失败。

两房间并行与单个进程故障测试分别执行，不等于生产容量测试或网络层故障穷举。服务器整体崩溃后的恢复、更多正常战斗组合、正式战场交互、DIY 编辑器迁移和 Commander 尚未实现。故障隔离测试会故意记录一次 Forge 进程错误，以最终 PASS 和两个进程退出断言为准。

原始日志：`.tools/forge-migration/{dedicated,dedicated-bo1,lan,mismatch,multiroom,rules}` 与 Unity `Editor.log`。菜单和命令见 [构建说明](../README.zh-CN.md)。

## IntegratedBattlefield 适配（2026-09-15）

IntegratedBattlefield 为联机战场入口，使用 Canvas、生命面板、手牌锚点、检视区、堆叠区、回合按钮与区域计数。

- 新场景真实 Starter 施法流程通过：20 → 17；战斗流程通过：20 → 19。
- 测试改为下一渲染帧射线命中校验，再通过 EventSystem 指针点击事件提交，检查重复点击仅响应一次。发现并修正玩家面板不接收射线、对手面板被牌堆遮挡的问题。
- 两个玩家面板、认输确认/取消按钮均命中自身；悬停检视调用无异常。未做真实鼠标拖动及多分辨率全覆盖。
- 该批 `battlefield` 目录结果和截图对应 IntegratedBattlefield 场景。
- 最终客户端显式以 Player 子目标构建成功；局域网 host/client2 与独立服务器 client1/client2 均 PASS、games=2。分别运行的 BO3、注册牌池换备、待选请求重连通过，服务器日志确认每局接受多次 ConfirmChoice 动作；以认输结束每局。

首轮新客户端原生回归超时，无完成报告。排查发现客户端构建默认继承了编辑器的服务器子目标，触发无着色器的服务器优化；构建菜单已显式指定 Player。另修复选择在同步拒绝后未恢复的问题：交互状态通知现在强制刷新界面，自动测试允许被拒绝的同一请求重新提交，仍由界面防重复提交。

首轮失败日志保存在 `.tools/forge-migration/integrated-first-attempt`；最终通过日志在 `lan` 和 `dedicated`。新客户端使用既有同协议独立服务器，本次未修改 Java 桥接或网络 DTO。最终 Unity 控制台无错误，`git diff --check` 通过，编辑器停在 IntegratedBattlefield 的编辑模式。

场景仍未完成：保留当前美术和布局问题供后续制作；复杂规则交互、特效、战斗连线尚未补齐。放逐缺少桥接数据，显示“—”；不显示无权威依据的倒计时。节点绑定与后续制作方法见 `Docs/ForgeBattlefield.zh-CN.md`。
