# MTGB 机制验证与复用

目标：主动盘点项目可达的 Forge 结算与交互，复用原生合法选项和共用控件，使选择、支付、结算与恢复能够完成。以新增规则断言和有证据关闭的缺口衡量进度。

## 先确认范围

从当前工作区读取 `AGENTS.md`、`Docs/MechanicValidation.zh-CN.md`，接续长期任务时读取 `Docs/MechanicValidationGoal.zh-CN.md` 的目标、验收标准与最新状态。涉及规则资料、翻译、卡图时再完整读取 `Docs/CardDataAuthoring.zh-CN.md`。沿用用户对暂停、语言、本地图和展示样式的决定；盘点或修改 skill 不自动恢复暂停的 goal。

结构发现按项目图工具规则执行；图不可用时记录错误，读取准确源文件，限定结论范围。机制盘点或规则／桥接变更需要刷新覆盖清单时，使用 `python -X utf8 Tools/ForgeBridge/MechanicCoverage.py`，不带 `--run`。纯局部展示修正、skill 文档维护和缓存清理不自动触发全机制清单刷新或效果回归。首次使用及交接读取 [references/verification-method.md](references/verification-method.md) 的证据口径与增量决策；涉及 Unity 展示时再读取 [references/ui-reuse.md](references/ui-reuse.md) 对应的控件、反例和验证入口。制作独立更新包、合并累计包、覆盖客户端、部署服务器或发布 Git 时，读取 [references/release.md](references/release.md)，按当前授权分别执行，核对安装基底、备份偏好、协议兼容及实际生效状态。用户要求清理本项目缓存或核对磁盘占用时，读取 [references/workspace-maintenance.md](references/workspace-maintenance.md)。

## 赛制接入的完成门槛

Arena 数字牌或专属赛制例外须另查官方 Arena 公告／补丁说明；通用综合规则和当前 Forge 行为不足以单独确认。主将进入统帅区可由拥有者选择全部移除或全部保留永久性改动，两条分支分别验证；原先仅验证保留的结果不能授予完整适配。反例及修正见方法文档“2026-10-24 Arena永久改动例外”。

用户明确安排赛制后，以最新请求更新当前范围和排期；历史普通1v1机制审查完成，只证明共用消费者，不代表该赛制已接入。2026-10-24用户恢复法禁与100张争锋，专属注册、统帅区、赛制规则和法禁局间换主将归F01；四人和其他特殊模式仍后置。验收沿实际组卡合法性→建房权威配置→注册主将/开局→主将施放、加税与区域选择→对局结束/下一局流程完成，并分别记录原生结果与Unity操作证据。当前计划和历史闭合范围分开，不改写旧证明。触发及纠正见方法文档“2026-10-24 赛制目标纠正”。

## 每轮开始的磁盘检查

继续执行 goal 的每个新轮开始前，先读取 C、D 盘实际剩余字节数并简要报告。C 盘小于 5 GiB 时先保存现场并正常重启当前项目的 Unity；D 盘小于 3 GiB 时先整理项目、删除已确认无用或过时且可再生成的产物。两者均触发时分别完成，不把一次处理视为另一盘已达标。具体命令、现场保护与清理范围见 [references/workspace-maintenance.md](references/workspace-maintenance.md#goal-每轮开始检查)。这是用户 2026-10-11 对后续轮次的持续授权，不另设确认步骤；未达阈值只检查，不重启或清理。轮指一次执行批次的开始，不是每次工具调用；维护不核销机制事项、不恢复用户暂停的 goal。

## 盘点剩余

用户要求继续排查对局界面时，先接续 `Docs/GameplayAuditProgress.zh-CN.md` 和对应窗口报告。区分已验证范围、明确缺口与待核对分类；不能用断言数或报告篇数回答剩余组数。要求彻查某窗口时，集中检查该消费者的布局、内容、权限及请求生命周期，已有相同证据直接复用，发现新差异才补跑。

执行 `python -X utf8 .agents/skills/mtgb-mechanic-validation/scripts/summarize_remaining.py`。查看生成的 `Docs/MechanicValidationRemaining.zh-CN.md` 和 `Tools/Validation/Reports/MechanicCoverage/remaining-plan.json`。登记后同步 `Docs/MechanicValidationWorklist.zh-CN.md` 顶端的当前进度；旧批次标为历史，避免便读表沿用旧数量，不能为更新文档重跑已完成效果。

当前活动事项以 [references/remaining-work.json](references/remaining-work.json) 为准，便读版见 `Docs/MechanicValidationWorklist.zh-CN.md`；TSV仅作包级索引。先选择具体事项编号并核对结束条件。审查项先归类冻结输入与旧证明，证据项启动前写明可达消费者、缺少的断言、真实操作/预期结果及UI复用或差异；不能拿“其他组合”直接开测试。某项已完成消费者/明确缺口归类，却同时承接未验证结果时，保留原编号、范围、转交断言与审查记录，将剩余工作标为补证据。用户继续goal后，满足上述条件的增量可与无关依赖审查并行推进；整理期间的临时运行限制随当前授权更新。新增事项记录源码/请求依据、旧证明为何不足、唯一归属、最小新增工作、关闭条件和前后数量；同义标签与数值变体映射已有事项。汇报完成/新增事项编号及分类数量，不用包数或批次数充当轮数。整理期间遵守当前暂停状态；catalog中的goalState只是该次整理快照，实时授权以用户及系统goal为准。

当前与用户后置事项分别计数，后置保留原编号/断言/证据，恢复条件记录在 remaining-work.schedulingPolicy。指挥官专属注册、区域/属性及四人接入按该政策和最新赛制授权安排；通用费用/目标/复制/融合等仍取普通1v1代表。排期依据实际依赖，不按牌名或出现“Commander”字样判断。A01顶层记录含重复ID与嵌套汇总，执行时归并准确输入/断言引用；不能用原记录总量减已核销输入数当净待验证量。

计数分开：结构条目、实际规则场景、适配器检查、Unity 套、开放边界包、执行批次和尚未分类项。准确原声明的结果关联数只统计证明来源；未关联数不能作为新增测试配额或估时依据，也不能把逐卡关联误设为完成门槛。先批量关联既有消费者及适用断言，只有明确缺失的规则结果、权限、生命周期或UI合同差异进入补跑表；实际补跑数量尚未确定时直接说明。TSV 工作包追踪边界，排期读取 [references/execution-plan.json](references/execution-plan.json)：每条开放边界恰有一个批次归属，共用检查按相同消费者/合同引用已有证据。生成器检查漏分配、重复分配和不存在的归属；批次数不是剩余轮数。报告必须先刷新再生成，不能从旧 Markdown 推算当前数量。保留无测试的机制、API、未归类声明、旧测试和未知调用链，复核后才决定合并或新增工作包。来源变化时更新 [references/remaining-packages.tsv](references/remaining-packages.tsv) 的受影响行及 `plan-provenance.json`，新增/关闭包同步执行归属。来源校验只检查计划是否需要复核，不证明计划覆盖全部含义。

新增成果要核销到包内边界，不能只因整个包尚未关闭就继续把全部范围列为未验证。[references/verified-progress.json](references/verified-progress.json) 保存首次验证的去重 case、断言、原证据哈希及包内原始/已完成/剩余范围；生成脚本检查原证据并显示部分完成。已完成首次验证与当前版本需回归分开，不能把两者混成“从零重做”。此进度账不替代 A06 的依赖与当前证据合并。

新登记的 UI 套只在确有完成结果后核销；独立但尚未登记的规则脚本保留专项审计与审查队列，不能塞进已登记场景计数。直接调用原生修改器的投影检查仍是适配器，不因展示通过计作真实施放场景。完整包移出开放排期时，将其编号事项同时存入 remaining-work 的 archivedPackages 与进度账 closedPackages.concretePackage，原编号和完成证据继续参与总量/哈希校验。清理时保留账本证明文件及替代关系，不能因删了旧结果而增加剩余工作量。

未登记的 Test-* 脚本先检查驱动与夹具：区分测试服务器、直接状态投影、原生输入合同和含实际操作的历史回归。`MechanicCoverage.json.reviewedScripts` 保存分类、驱动/夹具哈希及剩余审查；完整分类继续输出，源码变化重新进入未知队列。分类不进入效果 jobs/cases，不授予 PASS，不以卡牌实例化数量代替效果。历史效果脚本仍要核对原证据和登记重叠才能迁移。

整理独立选择与生成／事件效果时，旧结果范围同时读取基线实际运行、`verified-progress.nativeTargets` 的原断言和有实际结果的专项闭合审计，不能只读 A01 的 `api-*` 标签。缺少标签不等于未验证；共用 API 找到旧结果也不等于整张牌通过。相同效果链和保存值读取字段只共享核对记录，生产入口、操作者、区域、权限与生命周期差异分别保留。N57 的 [共享旧结果与重复引用](../../../.tools/incubob-art-and-reuse-1012/shared-outcome-scopes.json) 为本次范围依据：77 种实现都有旧有界结果，212 条重复声明无需各自建立核对任务；不是 77 个或 842 个新测试。

剩余排期以 `remaining-work.workloadReview` 的共用合同核对和明确补测表为准，原声明目录仅供追溯。原牌未实际施放过、链签名不同、尚未逐卡关联旧证据，都不能单独成为补测理由或完成门槛。按项目接入中可观察的请求、权限、字段及生命周期分支集中核对；Forge 内部数值、牌名及既有执行器组合不逐牌重验。确需补测时记录具体消费者、旧断言不足之处和最小真实操作；未完成核对不伪称通过。卡面全局 `storedReaders` 只是查找候选，先证明它读取本次产生的值；兄弟异能的其他记忆／随机分支不自动挂到当前根。已通过的原卡结果保持原身份，合同复用结论另列，不能改写成逐卡 PASS。工作量修正依据见 [N62复核](../../../.tools/workload-contract-review-1012/review.json)。

从历史剩余说明挑选样本前，先查当前原声明处置及后续增量结果；旧 `remainingScope` 不是当前待办。N63发现N44囚禁太阳缺口已由N51真实流程补齐，不能再次恢复验证。

读取冻结 payload 的后继时，用 [scripts/payload_descendants.py](scripts/payload_descendants.py) 按 `effectiveLine` 与根原文排除根节点；`chain` 按源代码行排序，不能默认首项就是根。最新纠正目录见 [N73 后继索引](../../../.tools/downstream-index-1024/index-summary.json)，旧目录仅保留历史身份。

**先判断工作是否必要，再比较证明。** 共用机制审查解决普通1v1缺桥接、缺UI、身份/权限错误和无法继续结算的接入问题；明确赛制另按专属接入门槛验收；未修改Forge的普通效果组合不自动要求整链、逐卡结果复核。只有新增项目请求/回调、身份/可见性/授权/恢复分支、本项目补丁影响的真实结果或实际失败，才把缺少的断言列为待办。仅发现牌链不同、力量公式不同、原牌未实测或旧证明不等于整牌PASS，应记录验证限制，不能因此启动泛泛合同审查。N64取消生成重复授权与延迟LKI/反身链的新增整链验证，复用Garth真实生成施放、权限期限、Kardur牺牲后选目标、独立触发记忆及延迟生命周期证明；保留70条准确原卡结果，未把其他牌改成PASS。N64曾据此关闭普通1v1接入范围，但N65已撤回该整体完成结论；仍须一次有界接入差异筛查。历史取消依据见 [实际取消的工作与依据](../../../.tools/redundant-work-disposition-1012/audit.json)。后续发现具体接入差异再登记，不恢复逐卡关联配额。 对未完成差异归类的整个目录，不能仅凭所有执行器都有旧结果或两个代表例子未发现新分支就授整体闭合。1015条未关联声明不等于1015条重复或1015次测试；先完成项目接入差异筛查，再决定是否补跑。更正依据见 [N65更正](../../../.tools/redundant-work-disposition-1012/closure-clarification.json)。

## 接入与修复

选择一个明确缺口，检查现有原生请求、桥接协议和 Unity 控件。按“原生合法选项 → 准确身份/数量/权限 → 共用控件 → 原生确认 → 恢复下一请求”的链路复用。费用、目标、合法性和结果由 Forge 决定。

先做能触发问题的最小真实操作；确定是规则、桥接、界面还是测试驱动问题，再修改负责该层的代码。夹具可安排开局，结算结果由真实施放/激活、支付和原生规则产生。确认取消、非法选择、空候选、费用不足等适用边界能恢复对局。

切换式选择驱动须按实际移除/确认选项判断已选状态，并对同一操作的无进展重复设上限。出现未知合同可冻结请求、短时保留原宿主供准确回应；不要不断写相同快照或为驱动误判重做已完成的付费结果。N49反例及证据压缩记录见方法文档。

规则断言与 Unity 证据独立：前者验证效果与结束状态，后者通过真实请求重放和射线点击验证可操作性及展示。长文本、隐藏信息、多对象、字体/语言变化各自按受影响条件采样；静态资料和截图数量不代替结算或点击证据。

保存值参与后续比较或重复停止时，先核对上游真实结果与保存值，再核对消费结果；两个默认零相等不能代替非零正例。驱动后段失败保留有效原前缀；要求同一宿主重置的断言必须来自同一真实流程，独立补跑不能拼成同局证明。

跟踪克隆或覆写前后的原对象时，先从真实初态保存物理 ID，后续按 ID 核对；观察字段 `originalName` 也可能随克隆卡面变化，不能用它替代稳定身份。读旧证据时先核对原选择、区域和实际支付记录，避免按牌名猜数量或把触发内部没有占栈付款快照误判为未支付。参见 [N53 原证据核对反例](../../../.tools/payload-proof-joins-1012/driver-corrections.json)。

BO3 归属或移除涉及辅助牌时，按原注册区域核对准确物理来源与下一局实际注册；新构筑限制与主机本场准确卡池授权分开。复用牌名控件前还需检查原生候选是否涵盖辅助牌源库，不能由相同控件推定候选完整。具体反例见方法文档的辅助牌 BO3 来源记录。

## 选择回归，避免重复

当前范围以最新赛制请求及remaining-work为准：法禁和100张争锋已恢复接入；完整子游戏、官禁多人/生产四人、时空、先锋头像、魔王、征召笔记/密谋牌继续后置。游乐设施和装置辅助牌组继续接入。排期先读取 `remaining-work.json.schedulingPolicy`；原输入和完整后续范围见 [scope-exclusions.json](references/scope-exclusions.json)。不把这些工作恢复为当前完成门槛或标成已验证；卡恩重开、BO3换备和普通1v1共用机制仍保留。卡组详情的不可用提示是展示检查，不是效果通过。

安排运行前先做减量判断，简要写入本批已有记录即可：

1. **先用证据**：核对具体消费者、合同、生产来源与已有断言；可覆盖的引用原证明，仅缺少记录时迁移结果。驱动修改只影响相应断言，不为统一版本/哈希重跑已通过场景。
2. **只补差异**：待测项写明具体入口、已有证据缺哪项断言及最小样本。“其他组合/其他消费者”是待分类范围，先查成具体分支；测试扩展由新入口、共享可变状态、权限/可见性差异、生命周期依赖、规则交互或实际失败触发，不以组合尚未穷举为理由。
3. **按分支取代表**：相同UI合同及联网传输/权限/恢复路径共享证据；数值和实例变化检查原生结果。控制归还、部分付款恢复或不同私有信息策略补差异请求，不按每种机制乘上所有语言、席位和网络条件。
4. **集中完成**：按 [execution-plan.json](references/execution-plan.json) 的推荐块及 remaining-work 的 schedulingPolicy，先对齐同一夹具/消费者能承载的多个输入，再集中补缺失结果；独立断言分别核销，批量执行并统一收尾。只做一组时记录其独立环境/阻塞修复或本批仅剩该组的原因。先修失败分支，再补受影响检查。仅为测试改变驱动时保留成功场景原版本，只重试失败或断言改变的部分。并行受可用内存约束，Unity场景操作保持串行。
5. **一次收尾**：每批使用现有结果/影响记录集中登记原证据、复用理由、修复和剩余差异；专门审计文档仅在复杂生产变更或闭包证据确需时新增。清单源变化后批末刷新/生成一次；纯方法/文档调整使用生成器 `--check` 和 skill 格式检查，不启动机制或全量构建。

异步资源失败使用实际读取失败和恢复节点验证；连续立即发出两次请求可能在读取前取消旧请求，不能用它证明旧失败回调守卫。驱动后段失败时保留原 FAIL，准确冻结有效前缀，只补失败差异；工具超时或结果仍为 RUNNING 不等于任务在运行，续跑前核对实际 Editor/进程状态。反例见 [语言资源故障增量](../../../.tools/locale-fallback-1010/audit.json)。

原生必选单候选、固定数量或没有合法攻击／阻挡者时可以自动推进，不凭机制名称要求额外窗口；按实际请求与阶段验证交互。攻击产生的效果等到真实触发阶段及下一请求，不以宣攻后空堆叠作为伤害触发已完成。具体反例见 [指示物增量](../../../.tools/counter-flows-1010/audit.json) 与 [拘留的空攻击／阻挡输入](../../../.tools/current-object-flows-1011/prefix-proof/result.json)。

运行包发布返回仍运行的进程句柄时，先等同一操作完成再启动依赖它的验证；安装新类后、清单发布前读取的 runtimeHash 不能当新版本身份。保留原版本限制及实际结果，不为统一哈希重跑；后续驱动在启动前核对受测类与已发布清单一致。反例见 [增减权限增量](../../../.tools/counter-addflags-1010/audit.json)。

临时编译共享原生类时，先叠加 `NativePatches.json` 中该类已发布的全部修改，再追加本次差异；发布前逐项核对旧修复仍在，不能用未打补丁的上游整类覆盖当前运行包。只改相互独立且守卫明确的分支时，保存逐字/条件等价比较并复用旧证明，不为新 class 哈希重跑。N31 的 GameAction 发布守卫发现旧 Craft 材料保留修复会被遗漏，已合并保留；库与坟墓场的列表方向分别用实际位置验证。

真实联网夹具启动前核对生产身份规范化后的唯一性、实际控制模式及原生默认字段语义；Windows共享读取/快照替换失败只短重试同一操作，条件判断一次读取一次状态。过期编号必须取曾有效的真实请求；单纯未知编号拒绝不能代替。驱动误判后冻结已通过流程，只补缺失断言；详见[网络夹具反例](references/verification-method.md)。

A01–A05共用一次条目→消费者→请求合同→证据/缺口的归类，R49只接收新发现且无归属的规则分支。参数、标签和同义形式保留分类引用；不同原生语义保留独立结果断言，断言可共享一次真实流程，启动次数不等于场景数。

UI按实际请求合同选择代表输入，不机械地为每个原生case重放一次：记录控件/提交分支、操作及可见席位、对象身份类型、数量/顺序、启用与确认门槛、取消和窗口生命周期，并引用原输入及点击证据。上述合同和格式路径相同、只是数值或合法对象实例变化时，核对新原生输入与既有证明即可；字段用途、交互分支、文案/资源/布局发生变化时，补主语言真实点击及受影响语言/边界。语言采样使用 AvailableLocales 的正式代码，确认 SelectedLocale 与资源 Ready 后再检查绘制；请求权限按 awaitingInput/seat 核对，JsonUtility 产生的默认请求对象不等于有效请求。语言和资源检查随受影响消费者执行，A06记录随本批证据填写，均不另起一轮重复全量。具体条件与负责批次见 execution-plan.json；不能只凭请求类名或相同截图判定可复用。

特殊表现/模式先检查项目可达性、现有支持与合同差异，再安排实现。未知项保持开放；确需新交互或支持范围决定时单列具体问题。通用控件能承接的分支仍按原生结果和合同补验，不因列在separate包就预设新UI开发，也不把尚未决定的模式静默移出goal。

逐任务依赖与证据需要可追溯，但自动失效计算/合并工具不是机制接入goal的必做产品。A06先用逐批审计记录变更、实际消费者、原证据/哈希、影响判断和未知依赖；未知范围保守扩大。自动化可后续优化，当前总指纹报告保持原状态，不据此伪造当前全量PASS。

修改前列出变更路径、受影响的请求/协议字段、引擎任务和 Unity 套及选择理由。仅新增测试时跑新增任务；局部界面修改跑相关展示套；共用分支修改跑实际消费者及边界。未知依赖明确标出，查清或扩大到相关消费者。全量留给阶段收尾、上游/运行包升级、核心请求路由改动或确实无法界定的影响。

局部控件的小修改可以直接对实际运行中的该控件采样，不必调用夹带无关检查的整套入口。例如指示物尺寸只核对双方符号的实际绘制范围、完整性、数字原排版及偏好刷新稳定性；不重复 BO3、目标选择、状态徽记、随机结果或整场密度测试。复用已有截图背景／输入不意味着那些机制本轮又获得验证。

当前工具采用总指纹，部分运行不继承其他任务 PASS。保存原始批次、失败和证据来源，历史结果标为“历史通过／影响待核对”；增量证据单独登记。建立可审计的逐任务依赖之前，保留工具的失效状态，不能手工伪造当前全量 PASS。详见方法文档中的证据字段和运行选择。

## 收尾与优化 skill

已有中文的复核分别检查正文、卡名、类别、模式标题和多行追加说明；只检查正文不能代表整个选项没有英文。BO3 本场牌组按会话快照核对，共享档案与磁盘刷新不能替换已登记的比赛卡池。具体反例与受影响消费者见 [实局流程增量](../../../Docs/LiveGameplayFixes.2026-10-13.zh-CN.md)，不因此扩大为逐卡重测。

生成异能文案、来源面板及排序改动使用原生实局请求做 UI 样本；确认的预览角色按合同区分：免费施放显示被施放的牌，移入牌库的位置选择显示被移动的牌，不能统一使用异能来源；操作者与受影响物理ID分别核对。卡牌译文存在不代表包含事件后缀、CARDNAME 或延迟效果的实际异能已翻译。目标候选核对可见列表与合法集合，禁用的无关异能仍出现在选牌列表也会误导。运行前核对受影响脚本与实际程序集时间/身份；刷新返回成功不代表新代码已编译。只补该分支真实输入、点击/拖曳和结算顺序，保留旧失败。递归卡牌 DTO 的序列化改动核对携带它的消息、拷贝和界面签名消费者；完整日志中的深度警告也计失败，不能只统计 Error/Exception。反例与修正见 [交互修复 2026-10-13](../../../Docs/InteractionPresentationFixes.2026-10-13.zh-CN.md)。

完成所选工作包需要明确规则断言、涉及的交互证据、相关回归及未验证边界。更新计划时引用批次/场景/断言；部分通过保持工作包开放，同时核销已完成的具体边界和事项。TSV与remaining-work.json同步维护开放归属，verified-progress.json保留首验与部分完成记录；关闭时将完整行、具体事项、原生/UI身份和审计哈希写入closedPackages；已登记消费者增量使用nativeIncrements/uiIncrements引用其job/result与A06证据，不因闭包要求重复增加首验，再从开放队列移除。nativeIncrements当前用于有真实付费操作的原生结果，须有登记任务、真实流程及审计哈希；不能用源码审查或直接状态投影核销。生成脚本核对关闭包不再开放、证据已登记且审计未变；仅关闭原行边界，不扩大为所有组合通过。无法复用且缺少用户展示决定的项目单列具体状态、所需操作和参考截图。

发现 skill 导致漏项、过度回归、错误归类或无法执行的命令时，在当前授权任务内修正对应一处规则/脚本/映射，记录“触发事实、错误决策、修正和检查”到方法文档的维护记录。用真实反例检查修正；新增脚本运行验证，skill 运行 `skill-creator` 的 `quick_validate.py`。使用中的反馈持续维护，不创建无人请求的后台任务，也不靠增加泛泛禁令解决问题。
