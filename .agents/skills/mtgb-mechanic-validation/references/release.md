# 发布已验证修改

发布以本轮用户授权为准，保留原验证批次；构建／启动不扩大为全卡池或长局性能通过。

先区分独立增量与累计合并，以及本次要执行的打包、覆盖安装、服务端部署、Git 提交推送；沿用仍属当前范围的已有授权。分别报告各项实际状态：包已生成、客户端已覆盖、服务端已上传、正式版本已切换、Git 已推送不能互相替代。当前项目发布偏好是不新增备份归档；核对原身份与哈希、保留审计元数据照常进行，已有版本的清理按用户具体范围执行。

1. 比较桌面累计包、正式客户端与线上服务的真实身份，按源码及原生运行清单确定两端范围。冻结当前构建输入和 Git 状态，再构建；生成字体缓存等差异单独检查，其他输入漂移需解释或重建。
2. 原生 Java 使用固定上游及 NativePatches 全部既有补丁编译，核对当前 reviewed 源文件，保持运行数据／目录身份。发布准确桥接源码、原生补丁及 Forge 来源，更新 origins、files、runtime 清单并逐项哈希校验。
3. 独立增量以已核对的目标安装版为基底，只纳入必要差异，记录基底程序集／运行清单及协议号，旧累计 ZIP 保持原字节；校验虚拟覆盖后的完整运行清单。累计合并则保留旧包所有仍有效路径的最新版本，再加入与正式桌面不同的文件，明确退役路径。两种包都校验 CRC、大小写路径唯一性及每项 SHA256；授权覆盖后用临时文件原子替换，保留 CardImages、Decks、Replays 和用户偏好。备份随用户当前指示执行，不把新建备份当作继续覆盖的必要条件，也不把“不备份”解释成删除既有数据。
4. 服务端有规则或协议差异时明确是否需要同步；双方客户端与服务器使用兼容版本。部署先在独立端口启动并查目录；切换前重新检查房间／玩家与现有连接。新发布目录与持久 Replays 分开，校验文件、执行权限及录像目录写权限；切换后检查正式目录、公网查询、PID／重启、原内存及 CPU 限额和其他服务。既有上一正式目录可原位保留供回切，不因此另制备份归档；删除旧版本属于单独的清理范围。
5. 桌面启动用隔离配置核对包身份、进入 Main 和资料就绪。更新文档／SKILL；执行用户授权的 Git 提交推送后，确认远端提交及该提交的 CI 结果，旧失败运行保持历史身份。记录尚未执行的公网实局／长局，不把目录查询算成对局证明。

实际脚本与最新路径从最近发布文档查找，不在 SKILL 固定日期、主机凭据或某次输出目录。大批量历史构建删除被工具拒绝时保留目标，改用独立 staging 或可逆无损压缩；这不是删除成功。压缩须校验原路径内容哈希和实际分配空间。

后台导出等依赖独立客户端的功能，须经一次脚本重载后从正常 UI 入口验证，不能只在测试驱动里指定临时可执行路径。编辑器登记应按项目持久化并随成功构建更新；清理旧构建前，先登记并验证保留版本，避免删掉仍在使用的后台程序。独立导出进程须从实际交付客户端启动并检查视频画面，文件存在或编码器退出成功不等于渲染正确。复用已验证构建时核对冻结源码输入；仅字体动态图集、Addressables 状态等生成差异按字段单独解释，不为重复生成而改写原验证批次。
