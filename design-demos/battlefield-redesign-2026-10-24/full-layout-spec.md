# E：完整区域布局与验证边界

前一版 D 只用单个录像时刻安排玩家面板，遗漏该时刻没有出现的区域。用户指出玩家指示物、对方神器／结界／旅法／战役、己方生物和延迟效果／徽记／地城缺位。本版不再借用空战场放 HUD，而是先为双方完整区域保留固定位置。

| 区域 | 双方展示内容 | 本轮验证 |
| --- | --- | --- |
| 玩家 | 玩家标识、50px 设计字号生命、牌库／墓地／放逐数量 | 两边独立显示 |
| 玩家指示物 | 中毒、能量、经验、辐射、票券；复用现有 Forge 图集 | 共 10 项可见 |
| 法术力池 | 白蓝黑红绿与无色，固定列距，无底框 | 共 12 项可见 |
| 地 | 双方各自独立牌列，横置标识 | 普通、四倍数量压力与左右浏览 |
| 生物 | 双方各自独立牌列、攻防、单张失调状态 | 普通场面共 8 张，未与其他区域合并 |
| 神器／结界 | 双方独立支援列，含食品等非生物衍生物 | 每方 3 个 |
| 旅法 | 与神器／结界分开，显示忠诚 | 每方 1 个，压力 4 个 |
| 战役 | 与旅法分开，显示防御 | 每方 1 个，压力 4 个 |
| 统帅区 | 双方独立入口与数量 | 两边逐项点开 |
| 徽记 | 双方独立入口、来源与数量 | 两边逐项点开 |
| 延迟效果 | 单独数量与期限摘要；展开查看具体来源 | 每方 2 项，分别点开 |
| 持续状态 | 单独入口，示例为君主；无卡图时显示文字，避免残留旧卡图 | 两边点开，并检查无卡图详情 |
| 地城 | 当前地城与房间，打开真实本地地城牌面及规则 | 两边点开；查看凡戴尔的失落矿坑／黑暗之池 |
| 公共状态 | 白昼 | 保留独立公共入口 |
| 堆叠 | 延续 C/D 的先后、来源与目标表现 | 保留右侧 |
| 详情／历史 | 左侧共用标签，悬停不抢历史标签，点击卡牌打开详情 | 保留既有交互 |
| 手牌 | 底部独立横排，不能侵占己方地与资源栏 | 两种尺寸下检查常态边界 |

布局基准为 1600×900。对方 HUD／资源位于其地牌上方，己方 HUD／资源位于其地牌下方；中间两条附属状态带用文字及红／蓝颜色区分归属。神器／结界、旅法和战役各自留出固定列。所有牌列的左右按钮放在自己的标题内，避免相邻区域翻页按钮抢位。大数量时只在各自牌列内部浏览，不把另一类永久物挤出去。

## 数据与资产

E 使用明确标注的组合展示数据，不是真实录像帧，不用于证明颜色标识、套牌合法性、费用、效果、联网同步或目标规则正确。A—D 的原录像样本保留。

`full-layout-data.js` 组合了录像现有卡图与少量现有本地卡图／中文资料，使用独立演示 ID，不修改生产卡库、翻译、卡图或规则脚本。新增普通牌的动态费用未接入引擎，详情不补造费用值。指示物图集原样复制，CSS 按现有 Index.json 定位；地城 TAFR/21 已与相邻的 20、22 实图核对。来源及哈希见 `full-layout-provenance.json`。

徽记来源画面沿用来源泰菲力牌图并在类型栏写明来源，不能把这张来源图当作一张新的原生徽记印次。持续状态没有图片时清除旧图，不画假卡面。地城当前房间和所有计数是本布局示例指定状态，不代表游戏刚刚结算出了这些状态。

## 与现有程序的对应

本轮尝试 graph `index_status`、`search_graph` 及候选路径的 `check_index_coverage`，均返回 Transport closed。改为读取有界源码；没有依据知识图谱宣称完整或无缺口。

- `ForgeBattlefieldController.Integrated.cs` 的 120—162 附近分别调用玩家指示物、生物、非生物地、支援、旅法、战役、法术力和堆叠展示。
- `ForgeBattlefieldController.Arena.cs` 的 175—215 附近保留支援、旅法、战役各自区域；正式接入时应复用这些分类及状态身份，不能从卡图外观判断牌类。
- `ForgeBattlefieldController.DuelLayout.cs` 的 `PresentPlayerCounters` 使用非零指示物及原有种类标签回退。
- `ForgeBattlefieldController.Emblems.cs` 的 `VisibleEffectMarkers`／`PresentEmblems` 区分玩家效果、公共效果、持续状态与延迟类，并复用原卡身份。
- `ForgeBattlefieldController.Zones.cs` 的 `ZoneCards` 提供统帅区、墓地、放逐等来源；正式接入仍需复用其公开／私有和可用选项边界。

这里只落实 HTML 结构与可见交互，没有授予机制覆盖 PASS，没有重跑或改写旧机制批次。

## 实际检查

`qa-full-layout.json` 保留实际浏览器结果：普通 1600×900、1280×720，外层视口两种尺寸的四倍数量模式，10 个战场分区均保留、10 个状态分组入口、10 项玩家指示物、12 项法术力均显示。按实际裁切边界检查可见卡牌，未发现与 HUD、资源、附属状态条或其他固定信息区相交，也未发现卡牌中心被覆盖；这不等于任意分辨率、任意数量或全部结算窗口均已验证。

两边各五个附属入口逐项打开，地城详情、无卡图君主状态分别核对。十列在四倍数量模式中逐项向右移动并返回起点，按钮不共用相邻列边缘位置。边界检查仅覆盖这些实际操作，不声称所有屏外对象都逐张点击过。规则、随机算法、服务器与正式 Unity 客户端均未改动。
