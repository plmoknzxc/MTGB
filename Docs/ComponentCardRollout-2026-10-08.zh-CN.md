# 组件卡面推广与原卡图切换

## 当前决定：恢复原卡图，保留组件实现

后续用户要求默认切回旧样式，并通过代码切换，不提供设置 UI。现已移除界面开关及其偏好读取，组件代码／资源全部保留；手牌、坟墓场、放逐新增原卡图顶部动态费用。当前行为及限制见[原卡图动态费用](LegacyDynamicCost-2026-10-08.zh-CN.md)。下文是此前组件推广的历史实现与证据。

## 后续纠正：栏位与忠诚异能

用户指出上一批截图的文字落点和旅法加减费用不正确。上一批“网格不溢出”证明不足以确认版式正确，109项检查不能据此表述为这些外观已经验收。

本次将旅法忠诚费用拆成 PSD 原生加／零／减底板和独立数字，正文按实际异能逐条排布，保留 +2、0、-1、-12、-X、-10 的准确顺序。传纪改为独立提示语、章节标记及对应正文。旅法标题／费用上移至其模板实际标题栏；传纪标题／费用也校正至模板中心。普通模板和历险原有坐标保留。

新增证据位于 `.tools/template-alignment-1008/`：按实际墨迹检查标题中心、逐行字形不重叠、正文区边界及忠诚费用身份／底板形状，不只检查 TMP 溢出标志。SDF 字符四边形含透明 padding，不用于字形交叠判据；以 glyph metrics、baseline 和 scale 计算字形墨迹范围。

迭代失败各自保留：英文长异能需要调整行距／正文起点；日文章节使用横线字符 `―`，已补解析；日文三异能版式需要减少异能间空隙。曾因工具重试重复启动截图驱动，增加一次派发标记，避免协程互相改语言。没有新增规则或联网结果。

最终 `result.txt`：244项局部检查通过，覆盖中英日四个版式代表、真实网格完整性、标题墨迹中心、逐行墨迹间隔、忠诚费用顺序／底板形状、章节／正文数量及正文所在区域。实际截图已查看。首次生成动态字形前的行高预估曾少算一行，改为先生成字形网格再测量；首次失败未覆盖。项目 skill 的 UI 复用参考补充同一验收口径，避免以后只以容纳检查宣称外观正确。

## 此前组件推广行为

游戏设置新增「原卡图」和「组件卡面」，立即刷新并保存选择；默认使用组件卡面。旧扫描卡图、旧渲染分支及此前的单卡试点组件均保留。区域浏览里的原生施放按钮独立于渲染模式，切回旧样式仍可操作。

取消妖精幻视师／碎骨巨人的试点白名单，支持的完整卡面共用模板：普通生物、瞬间、法术、神器、神器生物、结界、地、多色牌、旅法（三／四异能布局）、传纪、历险和普通双面牌的两面。手牌、公开区域浏览／选择、普通堆叠等现有消费者复用同一入口。战场紧凑卡图和悬停原扫描卡图继续沿用用户先前决定的样式。

以下情况自动保留原来的显示分支：战役正面、分割／余响、房间、堆叠上带 X 或已选模式的信息牌面、无目录身份／模板，以及文字无法在最低可读字号内放下的牌面。牌背、徽记和效果标记不生成公开组件卡面。因此本次是支持版式的全局推广，不是所有特殊版式都已组件化。

费用继续读取原生投影：手牌和具有相应区域使用权限的牌显示预览费用；没有许可的公开区域显示牌面费用；堆叠显示冻结的施放费用。区域身份和许可必须同时匹配，不能用其他区域遗留的许可数组误判。历险使用独立费用字段，双面牌按面身份选择名称、费用、文字和插画。显示层不计算合法性、扣费或结算。

## 模板与版式

`Tools/CardRendering/ExportCardTemplates.py` 从用户提供的 PSD 导出空白框架，保留源文件哈希，源 PSD 不修改。新增五色／多色／无色／神器／地的适用模板，历险、传纪、旅法以及四异能旅法模板；移除示例文字和示例数字。地与无色正文底板、旅法白色忠诚数字分别修正。

正文在固定纸面坐标内适配，不随窗口缩放或全局文字大小反复改变。无法适配时恢复原图。旅法四异能使用专用正文区域；较长费用在标题栏内增加宽度并适度缩小符号，避免覆盖卡名。组件内图片不截获点击。

## 实际证据与范围

证据目录：`.tools/template-rollout-1008/`。

- `types.txt` 和 `types-1.png` 至 `types-5.png`：20张本地印刷代表牌，17张组件、3张有意保留旧版式（Fire // Ice、房间、战役）。涵盖五色、多色、无色、神器／神器生物、瞬间、法术、结界、地、传纪、旅法、双面和两种颜色的历险。它们是目录投影样本，不是新增真实施放／结算场景。
- `final/checks.log`：手牌、坟墓场、放逐、无许可牌库以及堆叠的预览／牌面／冻结费用身份检查通过。此处通过反射复用显示入口，不作为规则费用算法证明。
- `pw4/result.txt`：83项中英日文字与实际网格完整性、起始忠诚、设置按钮真实射线／点击、即时刷新、偏好持久化、牌背隐私和原生请求身份检查通过。
- `header/result.txt`：26项长费用、双面背面及两种渲染模式的坟墓场施放按钮检查通过。使用真实历史原生请求快照，通过 EventSystem 射线和点击确认提交精确的原生 card 选项；回调捕获不代表本轮实际引擎结算。
- `export.json` 保留 PSD 来源与导出信息；`source-snapshot/manifest.json` 固定本批最终生产源码、导出脚本、测试驱动及模板 PNG 的哈希。

原始失败不覆盖：首次费用检查暴露许可未限定区域，已修正；之后英文四异能旅法放不下，改为专用 PW4 模板并只补受影响分支。测试驱动曾误用不存在的 `typeLine` 字段，改用现有类型字段后执行；这是驱动编译错误，不是生产编译失败。初版失败结果仍留在原目录，后续增量各有身份。

复用此前两张试点的原生结算证明，本轮没有修改 Forge 规则／协议，也没有重跑机制清单、全量效果或联网。长期机制 goal 保持暂停，首验工作量账不变。未穷举所有印刷、极端长文字和所有特殊版式；不把代表牌通过表述为全卡所有情形通过。
