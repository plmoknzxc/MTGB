# 起手按钮分组与对方回合自动让过

## 当前行为

- 起手「保留／调度」并排放在手牌上方同一个面板，右下角不再另外显示保留按钮。
- 保留后的回牌库底确认也使用这个面板；先保留再选择放回的流程不变。
- 通用选择面板移到场地中央，右侧堆叠位置不再承载这类选项。卡牌能力选择仍跟随源卡牌。
- 仅在对方回合的 `InputPassPriority` 中，直接使用 Forge 已计算的 `PlayerView.hasAvailableActions()`；结果为 false 时调用真人输入的 `passPriority()`。
- 自己的回合保留手动操作。调度、目标、支付、攻击、阻挡等输入不会自动确认。
- 每次拿到优先权重新检查，不设置“让过至回合结束”。此逻辑位于权威桥接进程，两个客户端不各自推算。

按照用户最终指定，完全沿用 Forge 现有判定，不增加独立产费或撤回操作的例外。**仅有可横置产费的地或产费生物，也可能被自动让过。**该标记来自 Forge 的费用/目标可用性预判，其超时回退也原样保留，没有另写规则判定。

## 验证

- Unity 真实对局：验证两个按钮存在、共享父面板、角落没有重复按钮；实际射线点击双方调度、保留、选择并放回一张，最终双方六张手牌。
- `python Tools/ForgeBridge/Test-AutoPass.py`：10 个真实 Forge 固定场景全部通过。无操作、横置地、条件不满足的地、无法支付的异能、只有地、只有产费生物自动让过；可用的免费瞬间、有费用可施放的瞬间、非产费起动式异能、返照保留手动优先权。
- `Test-ShockInteraction.py`：目标、支付及施放者让过仍手动；对手无可行动项时自动让过，电震真实结算 20→18。
- `Test-AttackDefenders.py`：三个生物攻击玩家/鹏洛客/战役的实际分配与伤害回归通过，对手无可行动项的优先权由自动让过处理。
- Unity Console 未报告错误；测试进程已退出。本次未重新做独立客户端或 Windows 构建验收。
