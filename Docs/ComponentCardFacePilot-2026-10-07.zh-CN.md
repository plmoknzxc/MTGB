# 单卡组件化试点：灰棕熊

2026-10-07。用户授权先做一张卡，覆盖公开区域、可用区域、费用变化与堆叠。长期机制 goal 保持暂停；本次没有核销长期包或增加其首验进度。

## 实现与范围

`ComponentCardFace` 将牌名、费用、插画、类别、规则文本、攻防与原始费用参照分成独立节点。复用已有绿色空框和原卡插画裁剪，没有修改卡牌资料或卡图。费用更新保留原费用节点、插画节点及纹理；语言或偏好修订会更新文字。

只接入普通、正面、非复制品的 Grizzly Bears／灰棕熊。战场使用紧凑版，手牌、区域列表、查看原始状态、检查面板、普通咒语堆叠和堆叠横向列表使用完整组件版。其他卡牌与特殊牌面保留已有渲染。灰棕熊没有异能，规则区空白是正常卡文，不代表长卡文适配已验证。

手牌、坟墓场、放逐区和公开牌库顶的可施放项来自原生合法选项；区域列表中的“施放”提交准确原生卡牌身份和请求号，只读查看不提交选择。没有许可的放逐牌仍不可施放，隐藏对手手牌不会因费用预览公开。

费用预览只对该卡、限定区域调用原生加减费算法，作用于复制的施放意图。卡牌原本费用与法术力值不变；加减费后费用通过独立法术力图标显示，并保留原始费用参照。原生 `MTGBCastingManaCost` 记录扩大到普通咒语，堆叠使用施放时冻结的费用，不把结算中康咒要求的额外支付记入施放费用。此补丁已同步 NativePatches.json 与生成器，避免重建丢失。

## 实际证据

根目录：`.tools/component-card-1007/`；哈希与证据索引见 `result.json`。

- 原生五条场景分别 PASS：正常 `{1}{G}`、阻力球加费 `{2}{G}`、翡翠徽章减费 `{G}`、加减同时 `{1}{G}`并取消付款重试、跨区域许可。跨区域场景实际从手牌、坟墓场（路拉斯）、放逐区（鲁莽冲动）、牌库顶（未来视野）分别施放，核对费用、实际横置地数量、堆叠身份和结算后身份。合计八次灰棕熊施放。
- 五条结果来自保留的各场成功批次，非一次统一重跑。最初普通堆叠未导出费用字段已修复；跨区域驱动误将墓地身份数组当对象的失败仅修驱动并重试该场。各成功结果保留原驱动哈希。
- Unity 专项 PASS：真实原生视图、四区域入口和施放按钮的顶层射线、准确身份、重复提交防护、按钮完整位于滚动视口、真实费用图标几何、130% 偏好字号、中文/英文/日文。修复了 TMP 单行裁切、紧凑版透明 Mask、列表施放按钮底部裁切与异步语言修订缓存。测试计数改为实际可见 Sprite 字符，不能用 TMP `spriteCount` 代替实际图标几何。
- `ui/live-cost-refresh.txt`：使用正常与加费两份真实原生视图更新时，费用／插画节点及纹理身份不变，费用内容正确刷新。
- `live-proof/result.txt` 与冻结 `trace.jsonl`：Unity 顶层射线点公开牌库顶→实际原生施放→自动支付→堆叠 `{2}{G}`→同身份进入战场。测试按钮查询起初只查 TMP 文字，实际付款按钮为已有 UI 控件，改按控件身份查询后继续同一付款；付款期间牌已离开牌库，继续核对的是已知待施放卡身份。原失败记录保留。演示文件交换的 Windows 占用通过有界原子替换重试修复。
- 因扩大普通咒语费用快照，增量回归原有 X 费用驱动的 normal、xx-increase、counter-tax 三场，全部 PASS：单 X、双 X 加一费、康咒额外支付不改变原快照。没有重跑其他机制。

## 可操作演示

`Run-ComponentCardFaceDemo.py` 启动真实 Forge 本地夹具，`ComponentCardFaceDemo.Start()` 在 Unity 编辑器连接它。夹具仅安排起手与场面，施放、付款、优先权和结算由原生引擎完成。初始场面含各区域灰棕熊及一张堆叠灰棕熊，可让过、从合法区域施放，也可施放手中的翡翠徽章改变后续费用。退出 Play Mode 或编辑器重载时会停止演示。这里是编辑器本地进程交互，没有网络服务器。
