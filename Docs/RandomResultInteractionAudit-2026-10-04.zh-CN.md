# 骰子、硬币与结果通知接入复核

固定 Forge 2.0.15，提交 `4ec5f1a2c32fa90ecb983a72b9eb47aa5c5d7676`。本轮继续共用交互覆盖，不将卡牌资料、翻译或卡图检查当作效果验证。

## 接入改变

原生 `PlayerControllerHuman.notifyOfValue` 的非施放法术力异能分支调用 `IGuiGame.message`。生产桥接之前将这个展示回调直接丢弃；这是源代码核对发现的缺口，没有把它描述成已经取得旧界面失败截图的复现。

现在按原生指定的接收玩家保存最近 16 条通知；通知序号与请求编号分开，通知不产生额外确认、不改变优先权或原生选择。只把固定 `RollDiceEffect.rollDiceForPlayer` 与 `FlipCoinEffect.flipCoin` 直接调用 `GameAction.notifyOfValue` 的公开结果标为公开。其他调用默认私人，即使来源能力属于 RollDice 也不自动广播。原生排除的玩家不会收到该私人通知；未知调用点／方法改名默认不公开。来源牌只在原生接收玩家可以看见、且牌面不是面朝下时附带；正文仍由原生决定。

Unity 显示四秒、无射线阻挡的简短结果提示，并提供可滚动的记录；重复快照不会重复提示或延长显示。记录入口在原生决策期间禁用，已打开的记录自动收起。观战投影只保留明确的公开通知。中文、英文、日文的骰子／硬币结果和选项使用固定字号；骰子数字直接取原生通知，不在客户端掷骰或推算。未知格式及普通私人通知保留原生正文，没有宣称所有原生通知文本都已本地化。

共用 `InputConfirm` 的两个按钮现在显示真实原生选项。例如 `ok` 是 Increase、`cancel` 是 Decrease；`ok` 是 heads、`cancel` 是 tails。这些编号不代表玩家可以取消结算，点击空白处也不会自动提交第二个值。可选骰值修改／交换仍提供明确的原生“保留原值”按钮；Krark's Thumb 的结果选择不能凭空取消。普通二选一费用沿用同一个界面，实际费用由原生执行。

## 实际规则场景

`RandomMechanicFixture.java` 只放置初始卡牌、地、计数和身材，并在原生优先权请求停住时只读观察牌库编号、掷骰／抛币记录。初始 Xenosquirrels 的两个指示物和 Vedalken Squirrel-Whacker 的 4/5 不冒充已经验证它们进战场时的效果。测试不设置随机结果；调用原生施放／激活、费用与目标选择，沿真实请求完成结算。

| 场景 | 核对内容 |
|---|---|
| Contact Other Plane 三档 | 种子 4、0、28 分别实际得到 3、12、20；支付四点法术力、占卜零／二／三、抽二／二／三，完整剩余牌库顺序与抽到的精确编号、原生优先权恢复 |
| Pixie Guide | 两次物理掷骰保留一个结果；被忽略的骰值通知、实际结果分支与费用 |
| Monitor Monitor 保留／重掷 | 原生多选确认保留，或选骰再确认、额外支付一点法术力；物理掷骰次数与保留结果分别核对 |
| Xenosquirrels 增／减 | 实际移除一个 +1/+1 指示物，修改选中的骰值；最终一个指示物与 1/1；减法将自然 1 改到 0，此时没有命中效果表、没有抽牌 |
| Night Shift of the Living Dead 增／减 | 原生支付一点生命，最终生命 19，骰值改动及对应抽牌／占卜分支 |
| Vedalken Squirrel-Whacker 交换两种身材 | 真实支付 Ebony Fly 的四点激活费；骰值与初始力量四或防御力五交换，Fly 成为 4/4 或 5/5，Whacker 对应数值成为原骰值 |
| Krark, the Thumbless 胜／负 | 同一种子实际抛币，分别选择 tails／heads；胜时 Shock 原牌与复制总共造成四伤害、原牌进坟墓场；负时原编号回到私人手牌且无伤害；支付一点、原生记录一次抛币 |
| Krark's Thumb 保留两种结果 | 两个不同原生结果出现后强制选 heads 或 tails，对应实际胜／负区域与伤害 |
| Mana Clash | 双方原生重复抛币直到同时 heads；14 条结果逐玩家对应 tails 的生命损失，最终生命 15／17；费用及原生优先权 |

共 **17 个实际规则场景**。双方接收的公开通知类型、值和行动玩家一致；两个接收玩家各自拥有独立通知编号。选择与费用、区域、身材和生命的断言彼此分开，不以“出现请求”代替结算结果。

另有两个单列的**适配器约定检查**，不计作卡牌效果：直接调用原生 notifyOfValue，验证接收玩家排除、手牌来源保密、能力 API 不能自动决定公开；连续 20 条私人通知只保留最后 16 条精确值和唯一编号。

## Unity 证据与早期失败

`RandomPresentationValidation` 重放真实二选一、可选骰子修改／交换、强制 Thumb 选择和重掷候选／确认请求，核对按钮中心实际射线命中、原生选项编号、旧编号、重复提交和非操作玩家。三语言另核对结果通知、记录滚动、自动消失、重复快照与观战投影；两个私人通知夹具明确属于适配器证据。没有把请求重放称作实际网络对局。

第一轮射线检查发现记录按钮被对手头像遮挡，移动到头像之外后复测。第二轮的“Private hidden source disclosed”是检查误将 JsonUtility 为缺失嵌套字段创建的空 DTO 当成泄露：原生 JSON 没有来源牌字段；改为核对空编号及各身份字段，并修正展示代码只对有效来源编号取本地名称。两个失败记录保留在 `.tools/random-mechanics-ui-attempts/`。早期测试驱动的 CounterType 方法编译错误、占卜确认编号／数量读取错误及未识别 InputConfirm 的增减分支不归为原生规则缺陷；请求和失败结果保留在 `.tools/random-mechanics/attempts/`。

完整引擎批次 `20261003T171302615990Z`、`20261003T172327703216Z` 和 `20261003T172730980880Z` 在生产界面／采样代码调整后主动停止，部分通过不当作整批通过；新批次以冻结后的输入重新运行。截图采样在点击前保留选择菜单，并等待 0.35 秒的现有入栈动画结束；此前快速切换夹具时旧 Contact Other Plane 动画牌面一度覆盖当前 Ebony Fly 的正确异能牌面，过渡截图另存到 `.tools/random-mechanics-ui-attempts/transition-sampling-*`，不当稳定状态证据。不带对局服务的回放只临时隐藏无对局提示条，结束后恢复，其他游戏控件仍接受原生射线检查。这里不证明所有动画过渡或中断时序正确。

## 保留的边界

多骰子的固定数值修正、指定结果、吸引力／平面骰、多个重掷和修改来源、费用不足、无费用、Night Shift 同回合限次、Ebony Fly 回合结束恢复及 Whacker 交换后跨回合／换区、额外玩家／控制玩家和真实断线／并发时序仍需分别补验。原生结果通知在固定数值修正之前发出，因此通知值不能一概称为最终结算数值；本轮代表场景没有该项固定修正。

其他卡牌及参数组合没有因为复用骰子／硬币选择界面就自动获得规则 PASS；其他结果通知接口、全部长文本和所有分辨率也没有自动获得展示 PASS。原生法术力异能的 notifyOfValue 写入 GameEventAddLog，此日志分支不属于本轮 message 通知接入；原生异能盾仍会显示英文名称／效果，新的三语言断言只覆盖选择提示、选项及随机结果。已打开记录后继续收到通知的实时刷新、跨实际会话重连／复用也没有单独证据。立体骰子／抛币动画、逐次结果动画不是本轮接入范围。覆盖清单继续保留这些缺口，总目标仍在进行。
