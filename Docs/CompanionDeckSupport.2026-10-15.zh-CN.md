# 行侣牌组指定与编辑接入

## 当前行为

- 卡组编辑主牌标题旁新增「行侣」，可查看十种行侣、指定其中一张、取消指定，并查看当前构筑条件与检查结果。若备牌已有该印次，指定只保存引用；若只有主牌中的该印次，移一张到备牌，否则按原复制数量限制加入一张。实际数量显示随原主备牌列表更新。
- `DeckDefinition.companion` 引用备牌中的一张，数量固定为 1，不增加主备牌总数。移走或删除最后一张对应备牌时清除标记，比赛永久移除／归属变更后也清除不可用标记。
- MTGB `.mdk` 用 `#companion` 保存指定；MTGA 用 `Companion` 分区。两者不会因为备牌分区再次列出同牌而重复增加数量。外部仅有行侣分区时补一张备牌。多个指定、数量非 1 或非行侣牌原子拒绝。MO 纯文本无法保留指定时明确拒绝导出。
- 构筑条件由固定 Forge 的 `Player.assignCompanion` 实际规则路径检查，不在 Unity 复制十套规则。显示检查在后台执行、串行、缓存及防抖，并丢弃旧界面结果；检查超时／失败保持未验证状态。
- 服务端独立验证印次、备牌归属及原生构筑条件。检查完成前的准备消息等待；后发牌组可取代前一检查，过期结果不会覆写新牌组。非法结果不提交牌组、不应用待处理准备。
- BO3 换备在备牌行侣卡上提供指定按钮，可切换或取消。撤销本次换备恢复原指定；准备后及观众无法操作。主备牌的本场总卡池授权仍使用原校验，指定信息不作为额外一张牌。
- 新牌组明确指定后，Forge 从原生合法候选中选取该印次；没有指定时不自动带入备牌中的行侣。老原生夹具没有新字段时保留其可选原生选择入口。进入指令区后的 3 点法术力特殊动作沿用原支付／取消／入手路径。

当前普通 1v1 范围内十种行侣都接入。指挥官联机仍按原范围后置；其牌组会显示未检查，不用仅检查主牌库的结果冒充指挥官构筑条件通过。

## 证据与限制

证据根目录 `.tools/companion-editor-1015`，最终源指纹、输入、运行包身份及旧失败在 `audit.json`。

- `native/result.json`：十种行侣各一个合法与不合法主牌样本，共 20 个原生检查通过。使用真实 Forge 卡对象、主牌库／备牌和原生限制判断，属于构筑条件验证，不是其所有牌面异能效果场景。
- `pay/*/result.json`：真实无状态注入对局。备牌同时有杰甘沙与卢拉斯，指定杰甘沙；只出现对应指令区行动，实际下三个地、支付三点后同一物理 ID 进入手牌，堆叠为空。旧取消／重试费用证明继续引用 `.tools/companion-payment-1009`，本次没有重复运行其未修改的费用分支。
- `no-designation/result.json`：真实开局中未指定行侣，备牌有杰甘沙也不出现行侣选择或指令区行动。
- `csharp/data-result.txt`：17 项持久化／导入导出、物理数量、无指定的 JsonUtility 空对象占位、拒绝无效指定、删除和本场永久移除检查通过。
- `csharp/ui-second-failure.txt` 的有效前缀：4 个实际编辑入口／清除／指定与 C# 原生调用检查，5 个服务端接收入口检查，3 个中英日条件文字检查通过。服务端检查注入可控制完成时间的原生结果任务，覆盖准备先到、旧结果、非法结果及 BO3 牌池；不是新的真实 UDP 或整场 BO3 证明。
- `csharp/layout-third-failure.txt` 的有效前缀：中英日 1.3 字号下 33 个长名及牌名／按钮间距检查通过。英文／日文原 46px 名字区失败后改为 64px 并下移按钮，其原 FAIL 保留。
- 最终 `csharp/result.txt`：8 个换备实际点击、更换／取消、60+2 物理牌池、撤销指定、准备锁定、观众限制、结果提示可见及位于页脚按钮下方不重叠的检查通过。旧准备布局隐藏了原状态行，本次在换备时激活并移至按钮下方；换备截图 `csharp/sideboard-companion.png`。
