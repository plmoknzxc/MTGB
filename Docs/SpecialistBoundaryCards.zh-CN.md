## 运行与验收口径

- `MTGB/Validate Specialist Boundary Cards`：逐项确定性验证。
- `unity.exe command mtgb_validate_project --timeout 180`：全项目检查，包含专项套件与两个牌组的连续对局回归。耗时较长时以 Editor 日志的最终结果为准，不能把 CLI 超时当作通过。
- 专项套件隔离 GameEvents，显式销毁测试规则实例，检查 Lua 错误日志；Lua 加载失败或运行期报错均判失败。
- 测试用夹具安排手牌、法术力和目标场面；施放、选择、取消、确认、让过走 `ApplyAction`，堆叠结算走双方让过后的正式检查点。
- 替代效应的伤害/区域刺激使用规则 API；不是全部经鼠标出牌触发。视图测试是双席 JSON 往返与客户端应用，不是实际网络传输。
- 全回归额外使用两个 60 张牌组各 16 个固定种子，检查合法操作、过期请求、双方视图与重放哈希；这不是穷举卡牌组合。

## 本批发现并修复

1. 可出牌预检只计算法术力，漏掉强制牺牲等非魔法力费用：预检与提交共用费用可支付检查。
2. 施放费用中的弃牌、牺牲、放逐手牌、展示手牌分支把 P2 当作离线电脑：仅离线对手保留自动选择。
3. OnInit 的来源在场能力在手牌/堆叠区域变化时被丢弃：记录其为卡牌固有声明，离场时不生效，每次进场重新绑定来源身份及时间戳；非固有临时效果仍正常失效。
4. Lua 效果处理中立刻执行状态检查，会嵌套调用其他牌的 Lua 筛选器：状态检查延迟到当前 Lua 调用结束后的正式检查点。
5. `ChangeDestination` 原先只转发回调，未使用空 Hook 下的目标区域值：补上内建区域替代，同时保留显式 Hook 的处理路径。
6. SDK 文档中的 `|` 和 API v1 模板与当前编译器/作者规范不一致：本批使用 API v2；不同单比特标志用 `+`，筛选对象从当前事件读取。
