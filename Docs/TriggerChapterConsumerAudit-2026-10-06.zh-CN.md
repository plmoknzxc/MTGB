## 实际规则断言

七条命名规则流程分别保存双方视图、原生请求、选项身份和失败尝试。章节结算证据独立于章节动画及此前背面激活验证。

## 界面修复与合同

`PresentAbilityOrder` 的缓存身份增加完整来源投影和偏好版本：双方同样的预览序号／描述不再复用另一来源的旧牌面；普通触发排序的标题、方向和按钮补齐中英日，标题和提示采用固定字号。来源卡图仍按已有本地语言／图片偏好选取。

`TriggerOrderingPresentationValidation` 重放双方真实排序的零选、部分选择、重排、全部选完请求，三语言射线点击准确的 `order:*`、`reset-order`、`confirm-order`。已排项目不可再次选择；选完才能确认；只读席位与重复提交被拒绝；查看战场／返回不改变字号。排序窗口没有原生取消选项，客户端不新增虚构的取消操作。

裂镜奇谭第二章原生合同为 `InputSelectCardsFromList`、最少 0／最多 2。原弃牌提示仅显示最少数量，因此错误显示“选择 0 张”；现按准确固定数量或范围显示，最少为零时说明“可弃至多 2 张”。`SagaChapterPresentationValidation` 单独重放双方的零选／部分／全部选择，核对现有手牌控件和右下确认。只读提交检查使用同一接收方视图；非接收方私有手牌展示未在此套补验，也不提供网络隐私证明。

改动仅为普通排序与弃牌提示；Forge 结算及卡牌资料未改。排序相关的生成预防效果三语言 UI、目标预览／旧替代排序中文 UI 另存本次回归，不增加首验计数。强制弃牌固定数量和非零范围仅作为提示适配器检查记录。

## 失败与证据口径

APNAP 驱动初次错误读取异能预览的 `controllerSeat`；预览没有该字段，实际堆叠才有。修正为来源编号属于请求方战场，再在堆叠断言控制者，未改桥接协议。原失败及两次驱动保留。

排序 UI 初次把原印次图片当唯一资源，忽略现有本地语言卡图偏好；随后把 JsonUtility 补出的空异能对象当成重排按钮的异能。分别改为核对语言偏好图片、按 `order:` 身份过滤，原尝试保留。章节驱动初次只处理 `FromHand`，实际输入为 `FromList`，零选后结果断言失败；修正为准确请求合同。手牌 UI 的只读卡仍可点击查看详情，不能用 Button 可点击状态代表提交权限；实际点击与提交守卫分别检查。

新增脚本通过全资产导入与类型检查后运行。图验证采用 Verify；相关路径 `metadata_changed/not_tracked` 回读源码，上游 `.tools` 排除范围直接读取固定版本文件。机器审计保存原生／UI／生产者哈希和对应版本。

R18 只核销上述同时触发与命名章节流程；其他章节、多个替代／控制组合仍开放。R47 的未知文本／资源过渡、R03/R36 的多方与嵌套控制、R15/R17 的其他私有权限以及真实网络保留原归属。全局指纹仍显示需回归，未手工转为当前全量 PASS。
