# 双方堆叠目标预览

## 结果与范围

补齐双方悬停堆叠卡时的目标预览：显示目标卡图、所属玩家和区域；多个目标横向排列，超出后滚动。同名目标保留各自原生身份；目标离开原区域后保留预览并标明离场。普通卡牌详情及堆叠移除会清除目标区。右侧堆叠和横向浏览共用详情控件，预览不提交选择。

桥接新增 `stackItems[].targets`，从实际 `SpellAbilityStackInstance` 的已确认目标与子异能读取，不读取当前选择草稿或解析描述文字。卡目标、玩家目标、堆叠目标分别保留准确身份。面朝下的目标对双方都隐藏原牌；其他隐藏区域按原生可见性处理。`leftZone` 只表示对象换区，不代表全部目标合法性。

运行包只更新三个桥接 class 与对应源码、清单，原生规则和卡牌资料未改。旧运行包哈希 `c12d2f6b92eafb432a71905307b1052dc58c514da1ffc2ccd7cbd21987a579f5`，新哈希 `6aea3341c28b3c6a992836fddd04f98f9612770b1bfa75c073c7482104f6a579`。原 R27 等历史证明保留原运行身份，未改写成当前通过。

## 定向证据

原生真实流程六条，均实际施放、支付、确认目标并结算，开局夹具只摆放初始卡：

| 流程 | 关键断言 |
|---|---|
| Reanimate | 对手坟墓场两个同名熊，准确选择其中一个；双方收到相同目标身份，结算原卡入场、失去两点生命，另一个留在坟墓场 |
| Soul Salvage | 自己坟墓场两个同名目标分别保存，结算两张原卡回手 |
| Pull from Eternity | 对手公开放逐卡的身份、拥有者和区域一致；结算原卡进其坟墓场 |
| Lightning Bolt | 玩家目标正确同步，结算对手生命 20→17 |
| Counterspell 响应 | 目标是具体堆叠实例；反击原咒语，放逐目标未移动 |
| Cremate 响应 Reanimate | 目标先离开坟墓场，原咒语目标预览显示离场；之后无效结算，未扣生命 |

选择未确认时，新咒语不会出现在公共堆叠。双方普通私有手牌保持隐藏。另有四项明确标为适配器的投影检查：对手隐藏手牌、双方暗置原牌遮蔽、公开放逐目标一致、玩家 ID=0；这些不计为实际规则效果场景。

Unity 共二十项检查：双方实际快照悬停、准确目标身份/区域、目标区只读、结算清理、三语言新标签、详情在屏幕内、多目标滚动及刷新位置保留、旧数据无目标字段回退、横向堆叠浏览的实际射线悬停和普通卡详情清理。后三类扩展布局是展示适配器，不增加原生规则场景。

主证据：[result.json](../.tools/stack-target-preview-1007/result.json)。截图：[多个同名目标](../.tools/stack-target-preview-1007/ui/opponent-grave-multiple.png)、[放逐目标](../.tools/stack-target-preview-1007/ui/opponent-exile-single.png)。生产源码、驱动、原始快照及失败记录分别冻结；清单全部 55,803 项哈希和三项运行包差异均核对。

## 影响与限制

这是目标/堆叠详情消费者的增量修复；不增加首次规则/UI数量，不关闭整个区域浏览或联网工作包。累计仍为 480 原生/37 UI 首验、25 关闭、20 部分、40 开放。此次验证双席位原生投影及 Unity 消费，没有授予真实联网延迟、重连或所有机制的通过。

图工具 `list_projects` / `check_index_coverage` 返回 `Transport closed`，因此使用准确源码及原生输入回退，没有当前图代次或全仓穷尽结论。保留测试失败：首次驱动缺隔离配置目录、堆叠目标未提交二次确认、隐私适配器未经过起手确认；初次 UI 误要求整个详情关闭，而普通卡悬停已接管，改为验证目标区清理。只重试受影响部分，未重跑其他机制。
