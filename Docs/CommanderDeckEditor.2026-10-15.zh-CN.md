# 指挥官牌组编辑与建房对比度

## 本次范围

按用户本次授权，仅恢复**卡组编辑**中的指挥官·官禁、指挥官·法禁、争锋选项。联机房间的赛制集合、两人对局模型、指挥官对战及多人规则没有开放；原机制 goal 保持暂停。

建房页复选框使用独立的深蓝底和浅色边框，禁用状态保留边框；勾选使用金色。底部连接说明使用更深底色及可见边框。原房间席位／观战区排版不变。

## 编辑行为

- 备牌标题行新增“主将 N”入口；指挥官赛制或已有主将指定时显示。
- 窗口列出已指定主将、主牌／备牌中的合法候选及当前选中的收藏牌。支持指定、替换、移回备牌，以及 Forge 判定合法的共同主将。候选分页，卡图分帧加载，规则检查后台执行并缓存。
- 指定时优先移动已有的实体牌；替换下来的主将移回备牌。主将单独保存，不作为备牌的重复引用。总数显示“主牌 + 主将”。
- 普通赛制切入指挥官类赛制时，只有**备牌实际合计一张、未指定主将且该牌具备主将资格**才自动移为主将。主将资格检查只投影这张备牌，其他主牌不会阻断迁移。两张同名备牌不会误迁移，已有指定不会被覆盖。
- 自动迁移同步已保存牌组中的对应分区；保留当前未保存主牌修改及脏状态，不把这些修改随赛制自动写盘。记录自身写盘后的目录版本，避免定时文件刷新打断异步迁移。
- 指挥官类赛制新增同名牌遵循单卡上限，保留基本地／明确牌面张数例外；已有重复牌不在切换时自动删除。
- 已有 MTGB／MTGA 主将导入导出及保存重载路径继续使用。切回普通赛制保留指定，入口仍可移回备牌，不静默丢牌。

## 规则依据与边界

新增独立的 `CommanderDeckInspector`，调用当前固定 Forge 的 `DeckFormat.isLegalCommander`、`CardRules.canBePartnerCommanders`、`getDeckConformanceProblem`。覆盖特殊可当主将的鹏洛客、格蕊斯、传奇载具、拍档及背景；界面用中英日问题类别显示原生检查结果，不显示原生英文错误正文。

构筑检查与现有日期禁牌表标示分别处理。完整检查仅适用于可由固定 Forge 准确解析的牌；含未接入 DIY 牌时会报告无法检查，不伪称构筑通过。现有行侣检查对指挥官牌组的未支持提示仍保留。本次不是指挥官对局、多人模型或所有特殊构筑组合的验收。

## 验证记录

证据目录：`.tools/commander-editor-1015/`。

- `native-audit.json`：8 次独立原生检查、16 项断言。普通／特殊主将资格、非主将拒绝、98+2 拍档、背景候选、59+1 争锋鹏洛客、标识色、重复张数及总张数。可重跑入口：`python -X utf8 Tools/ForgeBridge/Test-CommanderDeckInspector.py`。
- `ui-data-audit.txt`：24 项数据与 Unity 增量断言，包含两张同名备牌拒绝迁移、原指定保留、失效行侣引用清理、MTGB／MTGA 往返、保存重载、单卡／基本地上限，实际下拉事件和指定／移回备牌射线点击。
- `persistence-audit.txt`：8 项真实临时牌组保存检查，分别覆盖干净牌组及有未保存主牌修改的牌组；自身刷新不替换当前对象，主将写盘，未保存主牌内容不被写盘。
- `migration-delta-audit.txt`：2 项最终资格投影检查，未知／未接入的主牌不阻断唯一合法备牌迁移，异步检查中切回普通赛制会拒绝过期结果。
- `partner-ui-audit.txt`：3 项，共同主将按钮射线点击、第二张实体牌移入及结果牌组的原生构筑检查。
- `contrast-audit.txt`：复选框实际射线点击、DIY／赌注启用关系及 1.3 倍字号下禁用边框采样。`locale-audit.txt` 记录英语／日语资源就绪后的主将窗口采样，中文及三语截图已复核。
- 首次共同主将 UI 驱动以固定帧数等待，Editor 高帧率下先超时并访问未生成按钮。异常栈仅在测试的 `MCPDynamicCode.Run`；保留 `partner-driver-failure.txt` 和原截图。原生候选完成后，从同一有效窗口续跑，改用实际经过时间等待；不记为产品崩溃或重复通过。
- 双主将截图另发现复用按钮未更新位置的实际布局问题：主将数从一变二后首个按钮仍在中央。新增主将窗口专用按钮定位包装，不改其他选择器合同；`layout-delta-audit.txt` 的 5 项检查单独核对候选数二变一、主将数一变二的重新居中及按钮间隔。旧错误截图保留为 `commander-partners-before-layout-fix.png`。
- 最后一次 Editor 会话出现用户目录 `Preferences/Overlays/CanvasesSaveData.asset` 写盘清理错误，来自 Unity 编辑器偏好文件移动；单独记录环境噪声，不声称全控制台零错误，也不当成新对局规则失败。
- 上述布局检查写盘全部通过后，原 D3D12 Editor 发生 `8007000e`／`Unrecoverable GPU device error` 原生崩溃。尾日志保留为 `editor-gpu-crash-tail.txt`；以临时启动参数 `-force-d3d11` 恢复编辑器，不改变项目图形设置或客户端构建配置。恢复时的场景副本保存在证据目录 `recovery-scene-backups/0.backup`，未覆盖 Main 场景；重新打开的项目路径和实际 Direct3D11 设备已核对。有效前缀保留，不将图形设备崩溃误记为 C# 规则异常。

仅刷新机制分类清单，没有启动全量效果任务。新增独立检查类已本地编译、同步对应源码并刷新运行清单；没有替换原生规则类或修改对局桥接请求。没有客户端打包、桌面覆盖、服务器部署或 Git 上传。
