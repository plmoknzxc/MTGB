# 战场交互验证记录

日期：2026-09-22。环境：Windows / Unity 6000.3.22f1 / IntegratedBattlefield / Play Mode / Direct3D12。

## 方法

测试运行真实 OnlineMatchSession 和无窗口 Forge Java 子进程，通过 ForgeBattlefieldController.Present 呈现每个席位的视图。每次点击前执行 EventSystem.RaycastAll，断言按钮未被遮挡且可交互，再派发 pointerClickHandler；不直接改生命、永久物或战斗状态。测试替代的是人的选择，不替代规则引擎。

本次重跑已有施法及无阻挡攻击测试，并扩展 `Assets/Scripts/Editor/ForgeBattlefieldValidation.cs`，加入阻挡测试、请求记录、非法候选和重复响应检查。未修改运行时规则或战场逻辑。

## 结果

| 项目 | 实测结果 |
| --- | --- |
| 起手确认、下山脉 | 通过场景按钮提交并由 Forge 推进 |
| 闪电击选择玩家目标 | 点中对手生命面板，进入真实费用及堆叠流程 |
| 费用、优先权、结算 | 选择山脉产费、支付红色费用、双方让过，生命 20 → 17 |
| 无阻挡攻击 | 正常施放怒火鬼怪，选择敏捷攻击，生命 20 → 19 |
| 阻挡 | 双方正常施放怒火鬼怪；第三回合一方攻击、另一方阻挡 |
| 取消与重新指定阻挡 | Forge 视图中的阻挡者数量按 0 → 1 → 0 → 1 变化 |
| 战斗伤害与死亡 | 双方鬼怪均离开战场并进入各自坟墓场，双方生命保持 20 |
| 重复点击 | 同一个 UI 候选连续派发两次点击，仅执行一次回调 |
| 已提交请求重发 | 第二次 ApplyAction 被拒绝 |
| 非法目标候选 | 在目标请求中提交越界候选编号，被 C# 会话入口拒绝；提交前后席位快照一致 |
| 隐藏信息 | 每个被检查席位的对手 hand 身份数组为空 |

阻挡使用内存测试牌组：30 张山脉（10E/376）和 30 张怒火鬼怪（10E/224），固定随机种子 4，双方通过正常洗牌、起手、回合及施法流程建立场面。该测试牌组不满足通常的同名四张限制，不用于验证牌组合法性；没有改写玩家牌组文件或卡牌脚本。

## 重复运行

打开 IntegratedBattlefield 场景，依次运行菜单：

1. `MTGB/Forge/Validate Battlefield UI`
2. 等待 result.txt 显示 PASS，再运行 `MTGB/Forge/Validate Battlefield Combat`。
3. 等待 combat-result.txt 显示 PASS，再运行 `MTGB/Forge/Validate Battlefield Blocking`。

运行输出位于 `.tools/forge-migration/battlefield`。本次结果副本保存在 `Tools/Validation/Reports/Battlefield-2026-09-22`，包含结果文本、截图和新增测试的 JSONL 请求/状态轨迹。轨迹用于本地诊断，会先后记录两个席位各自可见的手牌，不是可广播给玩家的日志。

## 结论边界

这些结果确认当前场景的基本施法、玩家目标、单生物攻击和单生物阻挡链可用。测试绕过联机大厅和网络传输，由同一个测试进程切换双方席位；不是双客户端联机验收。

尚未覆盖：生物目标、取消施法、多目标/模式、多生物攻击、多重阻挡与伤害分配、先攻/践踏等机制、拖拽操作、目标等待期间的窗口缩放，以及本轮 Windows 构建。非法候选测试止于 C# 会话入口，不能当作本轮 Java 协议非法目标测试。重复提交覆盖等待确认时的拦截，不等同于跨重连的旧请求回放。

本次通过不表示全卡或全部战场交互已验证，也没有证明此前的窗口缩放崩溃已经修复。
