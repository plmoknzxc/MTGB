# 主菜单角色动画的制作、接入与验收

飘萍皇「潮灯」的定稿为 1536 × 864、30 帧每秒、8 秒循环。游戏使用定稿的网格、图集和动作参数，雨点、涟漪和花瓣单独画在人物后方。制作预览里的背景没有这层天气。以后做新主题时，按下列顺序检查，可以在成本最低的阶段发现问题。

| 阶段 | 先做什么 | 用什么判断可以继续 |
| --- | --- | --- |
| 定原画 | 锁定人物、背景、眼睛素材及画布尺寸。记录源文件哈希，所有部件使用原画坐标 | 在原尺寸叠回静帧，比对脸、手、发丝和伞骨。脸与衣服交界处也要看 |
| 分层与补画 | 沿遮挡关系分出前发、后发、袖口、伞面和刚性的伞骨。从袖口后面延长真正穿过袖口的发丝。跨画框的发束要补到动作范围以外 | 先只渲染静止、最强风、反向回落三个姿势。放大查看发梢下的水面和衣褶，排除重影、截断和移动的衣料碎片 |
| 绑定动作 | 让发根跟头、两只手跟握点、伞骨跟伞柄。按整绺曲线弯曲头发，让发尾晚于上半段。把呼吸分散到肩胸和衣袖 | 跟踪有墨线的部位。量发束和伞骨的弧长、两手交接处的相对位移，再看起势、峰值和回落能否连成一个动作。透明网格的最大位移不能代替画面检查 |
| 导出定稿 | 用实际 Cubism Core 加载模型、纹理和动作，先抽查关键姿势。确认后再渲染整圈并冻结哈希 | 检查眨眼、发梢的回落以及最后一帧接回第一帧。改变打包方式时，用同一画幅逐帧对照。一次只改造成缺陷的层 |
| 接入游戏 | 从同一套定稿数据生成游戏资源，走正式的主题选择和动态开关。编辑模式和关闭动态时显示静帧 | 在 Unity 的实际主菜单看静止、强风和闭眼三个姿势，看手、伞骨和发梢，并验证关闭、再开启、换主题、离开菜单 |
| 测量与归档 | 在相同分辨率、帧率限制和窗口状态下交替测静态与动态。记录中位数、P95、实际纹理格式、绘制次数和离开后的驻留资源 | 性能数字注明设备、Editor 或 Player、采样时长。先在空目录重建并对照哈希，留下定稿、源图、脚本、工具版本和小型验收记录，最后删旧渲染与缓存 |

潮灯的 8 秒待机包含两次轻呼吸和一次调整握伞。吸气时先看胸前衣褶，肩袖轻轻跟随，呼气时衣襟慢慢落回腰带上方。单独检查呼吸参数时，1536 × 864 原画上的胸前衣褶上下约 3.6 像素，袖口上方纹样约 1.7 像素。分别跟踪这两处，可以发现单边耸肩。再打开完整动作，检查上下两个握点、两手间的伞柄和衣摆底边。发根跟头部倾动，发身延迟约 0.23 秒，发梢约 0.58 秒。伞面上沿是原画的裁切边，收住前三排网格向画面内的位移。导出后逐帧检查伞顶，尤其是倾头到最大幅度时。[Unity 主菜单 8 秒实录](../Captures/Menu-Emperor-Tidelights-Canopy.mp4)

### 潮灯的复现入口

本机制作目录为 `F:\AI\Live2D\Emperor-Trial-20261119-233514`。`art/approved-source` 固定经确认的原图，`art/v4` 保存分层和动作配方，`review/reproduction.json` 记录依赖版本和文件指纹。`preview-canopy` 保存当前视频和动图，`preview-breath` 留作上一版对照，游戏只读取项目自己的资源。

在 MTGB 项目根目录运行以下命令。第一条制作命令在独立的 `rebuild` 目录生成并校验模型，第二条从同一套几何数据和纹理生成 Unity 资源。需要重新出视频时，直接运行 `Rebuild.ps1`，省略 `-ModelOnly`。

```powershell
$trial = 'F:\AI\Live2D\Emperor-Trial-20261119-233514'
& "$trial\Rebuild.ps1" -ModelOnly
py -3.12 Tools/MenuArt/Export-Tidelights.py "$trial/rebuild/model-atlas-rig.json" "$trial/rebuild/model/Emperor.model3.json" Assets/ThemeSources/Tidelights --verified-by "$trial/review/reproduction.json"
```

导出后，在 Unity 中运行 **MTGB → Themes → Rebuild Tidelights artwork**。主菜单从 `Themes/Tidelights/art.bundle` 播放该次打包的动作。验证独立客户端时使用这份资源包和同目录的 `theme.json`。

角色在游戏中用一个网格绘制。呼吸、握伞、头部和两段发丝的位移随顶点一次上传，平时只更新姿势参数。三个眨眼形状、六个伞尖雨滴的起点都取自同一帧的定稿。角色循环和天气各自计时，人物回到起点时，已离伞的雨滴仍会继续下落。打包时保留图集原始纹素密度，关闭 mipmap 和 CPU 可读副本。[游戏导出器](../Tools/MenuArt/Export-Tidelights.py) · [菜单播放入口](../Assets/Scripts/UI/TidelightsMenuMotion.cs)

### 2026-11-20 首次接入时的游戏内测量

Windows，Unity 6000.3.22f1 Editor，Direct3D 12，i9-13980HX，RTX 4080 Laptop，游戏视图 1920 × 1080。限制到 60 FPS，角色和天气以 30 Hz 更新。打开 Main 场景，选潮灯并开启动画，在 Play Mode 用 Unity MCP 的 `execute_code` 运行探针。它交替关闭和开启四个窗口，每次先预热 1 秒再记录 3.5 秒，结束后恢复帧率和原开关。[复测脚本](../Tools/Validation/ProfileTidelightsMenu.cs.txt) · [定稿原始数据](../Tools/Validation/Reports/TidelightsMenu/accepted-2026-11-20.csv) · [旧版基线](../Tools/Validation/Reports/TidelightsMenu/previous-2026-11-20.csv)

| 实际主菜单 | 静态，422 帧 | 动态，421 帧 |
| --- | ---: | ---: |
| 主线程，中位数 / P95 | 1.81 / 2.45 ms | 1.94 / 2.64 ms |
| GPU，中位数 / P95 | 1.02 / 1.38 ms | 1.16 / 1.72 ms |
| 帧间隔，中位数 | 16.67 ms | 16.67 ms |
| 绘制调用，中位数 | 12 | 14 |

单独推进 240 次人物和天气更新，CPU 耗时中位数由旧版的 1.187 ms 降到 0.321 ms。Windows 桌面图集采用高质量 BC7，人物图集占 2.00 MiB 显存，动态场景底图占 0.63 MiB。角色的托管几何、姿势和雨滴锚点数组共 0.51 MiB，提交给 Canvas 的人物顶点和索引数据为 0.45 MiB。驱动实际分配的缓冲区大小未单独测出。源模型图集另存为无损的 2048 × 1024 RGBA，非桌面构建沿用默认导入设置。全场景每帧 GC 分配中位数在两种模式下都是 586 字节，这个计数包含 Editor 的分配。

连续开关三次，文件已有系统缓存时，开启到首次画布更新耗时 5.48–7.50 ms。关闭或离开菜单一帧后，动态纹理、人物、天气和专用材质的存活数量均为零。切换静态主题再返回，动效只创建一份。第 0、69、76 帧分别核过静止、强风和闭眼。实际游戏强风帧的右侧发束与 Core 参考位置相差不到 1 个原画像素。上述耗时只覆盖这台 Windows 编辑器。[Unity 主菜单实画面](../Captures/Menu-Emperor-Tidelights-Unity.png)

清理后，从归档的三张绘制源图重新生成的模型、图集、动作及 Unity 导入数据与定稿逐字节一致。制作目录的 `review/reproduction.json` 记录这次复验。项目内保留静态主题原画、菜单用图、定稿动作数据、图集和着色器。旧人物整图和眨眼分层已归入制作源文件，旧的逐格拉伸脚本和试制录像已移除。
