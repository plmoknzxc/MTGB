# MTGB 联机架构

## 运行模型

正式联机使用独立权威服务器。客户端只提交 `GameAction` 意图并锁定后续规则输入，不在本地推演隐藏状态。服务器在所属房间的 `OnlineMatchSession` 中恢复并推进完整规则状态，再分别为玩家 1、玩家 2 生成允许看到的视图。动作被拒绝或确认超时时，客户端进入 `Resyncing` 并请求自己的脱敏权威快照，视图哈希确认后才解锁。

## 构建与启动服务器

1. 在 Unity 菜单执行 `MTGB/Networking/Build Dedicated Server`。
2. 启动：`Builds/Server/MTGBServer.exe -batchmode -nographics -mtgb-server -port 7777`。
3. 客户端在主界面选择“联机对战”，先在连接页输入服务器 IP、UDP 端口、房间号与建房规则。不存在的房间号会按首位玩家填写的生命、BO1/BO3、允许系列与 DIY 开关创建房间；每局先手由服务器重新随机决定。连接成功后整页切换到独立的房间准备页，可选择本局牌组、查看两名玩家状态并准备。BO3 局间会再切换到独立的全屏换备页，主牌与备牌以卡面网格显示，直接拖到另一侧即可移动一张；房间准备页不会常驻显示换备控件。已有房间号会加入并显示房间现有规则。大厅内断开或返回会退出房间并释放席位。

也可以通过命令行构建：

```powershell
Unity.exe -batchmode -quit -projectPath D:\project\MTGB `
  -executeMethod DedicatedServerBuildMenu.BuildFromCommandLine `
  -serverOutput Builds\Server\MTGBServer.exe
```

公网部署时，需要在服务器防火墙与云安全组开放所选 UDP 端口。

## 本机双客户端联调

项目使用 Multiplayer Play Mode 2.0.2，无需构建正式独立服务器即可同时运行一个服务器和两个客户端：

1. 先保存至少一个可用牌组。
2. 执行 `MTGB/Networking/Prepare Local 2-Player Session`。该命令会建立互相隔离的 `player-1`、`player-2` 配置，并打开 `Window > Multiplayer > Play Mode Scenarios`。
3. 选择项目自带的 `Assets/Settings/PlayMode/NewPlayModeScenario.asset`；它已配置 Main Editor、Player 2、Player 3 三个实例。MPPM 2.0.2 下保持 `Stream Logs to Main Editor` 关闭；需要日志时直接查看对应虚拟工程的 `Library/VP/<实例>/Logs/Editor.log`，避免工作线程日志转发触发错误风暴。
4. 从 Play Mode Scenarios 窗口启动场景。准备命令会让 Main Editor 自动作为独立服务器，带空格的 `Player 2`、`Player 3` 实例名也会分别映射到两个客户端配置，自动连接、提交牌组并准备。

三编辑器会占用较多内存；如果系统资源不足，应关闭其他大型程序，或改用“局域网建主 + 一个 Additional Editor”的双实例方式做日常交互测试。三实例主要用于独立服务器边界和最终冒烟。

准备命令会把 `player-1`、`player-2` 写入 `Library/MTGB/OnlineProfiles`。附加编辑器会从真实项目根读取同一套 `CardDatabases`、`CardImages`、`CardScripts` 和开发牌组，不依赖各实例互相隔离的 `PlayerPrefs`。

联机大厅也可以手动切换“客户端配置”。每个配置分别保存服务器地址、端口、玩家名、牌组和重连令牌，不会互相覆盖。

## 局域网建主

不启动独立服务器时，可以在主界面的联机大厅直接建立局域网主机：

1. 建主玩家进入“联机对战”，在连接页设置端口和房间规则，然后点击“创建局域网主机”。
2. 加入玩家在同一局域网内输入建主电脑的 IPv4 地址和相同 UDP 端口，点击“加入主机”。
3. 连接后双方进入独立准备页，各自从已保存牌组中选择本次牌组并准备。主机同时承担权威服务器和玩家 1 客户端；第二位玩家作为玩家 2 加入。

该入口只使用直接 UDP 连接，不使用 Lobby、Relay 或 Locus。若两台电脑无法连接，需要允许游戏通过 Windows 防火墙，并确认路由器没有启用客户端隔离。公网或长期运行仍建议使用独立权威服务器。

也可以使用启动参数指定角色：

```text
-mtgb-server -port 7777
-mtgb-client -address 127.0.0.1 -port 7777 -room main -mtgb-profile player-1 -displayName "Player 1"
```

服务器和客户端日志均包含 `match`、`seat`；动作日志另外包含动作序号、动作类型和状态哈希前缀，便于对齐三个实例。

## 已实现协议

- v7 游戏版本、协议版本、数据库模式和卡牌/Lua 分类内容哈希握手；拒绝时会明确指出是卡牌数据库还是 Lua 脚本不一致。
- 两个玩家席位、牌组提交、服务器牌组合法性校验、准备状态。
- 房间号、房间生命值、BO1/BO3、服务器每局随机先手、允许系列与自定义内容开关。
- 服务器检查主牌至少 60、备牌最多 15、复制数量、卡池、系列与 DIY 规则；BO3 局间只允许在本轮注册的主牌和备牌卡池内换备。
- 每局结束后记录系列比分；未结束的 BO3 返回房间准备页进行换备并重新准备，系列结束后可重新准备开始新比赛。
- 单服务进程中的多个独立房间和 `OnlineMatchSession`。
- 服务器生成随机种子并权威开局；客户端只接收自己的脱敏玩家视图。
- 支持伦敦调度：双方依先手顺序选择保留或重调，全部保留后按各自调度次数选择牌置于牌库底；HUD 和选择提示明确显示谁是先手、谁是后手。
- 动作序列、预期状态序列、服务器合法性校验。
- 每个动作后的玩家视图哈希。
- 哈希不一致时由服务器发送对应席位的脱敏快照。
- 断线席位保留、重新连接、认输和对局结束。
- 客户端交互状态 `Idle`、`Submitting`、`Resyncing`、`Disconnected`。
- 动作请求 ID、十秒确认超时、拒绝恢复和超时后的权威视图重同步。
- 客户端战斗中断线后自动重连，战斗 HUD 显示剩余宽限时间；重新连接后保持 `Resyncing`，直到玩家视图哈希确认。
- 服务端为断线席位保留 30 秒重连窗口；窗口过期时由仍在线的对手获胜，双方均离线时终止对局。
- 每条连接使用单调请求 ID 门，拒绝缺失、重复和乱序请求，并用认证席位覆盖客户端声明的玩家 ID。
- 心跳、45 秒空闲断开、512K 字符消息上限、十秒窗口限流，以及名称、房间号、牌组和操作字段边界。

## 联机验证

`MTGB/Networking/Validate Protocol` 或 Unity CLI 命令 `unity command mtgb_validate_p1` 会验证所有 `GameActionType` 的协议往返、开局先后手与调度视图、动作请求关联、客户端输入状态机、重连窗口、重复和乱序请求、认证席位覆盖、双客户端配置隔离、隐藏信息投影、视图篡改检测、内容哈希握手、消息防护、房间配置和双房间状态隔离。

`MTGB/Validate Project` 还会同时运行规则选择、确定性、复杂卡牌特性和协议验证。新增规则动作必须先进入 `GameAction`，并为规则层验证补充对应场景；网络层不需要为每种规则动作增加专用消息。

## 安全边界

服务器是规则和胜负的唯一权威。客户端不会收到对手完整牌组、隐藏卡牌定义或权威回放；对手手牌和牌库以无身份的临时对象表示，公开时才发送印刷信息，重新进入隐藏区域后更换身份。面朝下永久物保留公开对象 ID、控制者和面朝下特征，但只向其控制者发送真实印刷身份。服务器发送给客户端的动作结果也只包含该玩家的视图哈希，不包含完整状态哈希或隐藏事件明细。

自定义数据库会被标记为自定义内容，只有房间明确允许且三端内容哈希一致时才可使用。日志不记录重连令牌、完整牌组或隐藏卡牌身份。
