# 联机入口：房间列表与建房分离

## 玩家流程

- 联机对战先进入房间列表。右侧编辑游戏内名称、服务器地址、端口；左侧刷新并加入房间。
- 刷新同时查询局域网及填写的服务器。查询不启动对局客户端，不入座，不建立房间。同一服务实例通过多个地址发现时合并。
- 建立房间展开局域网／服务器。局域网直接进入独立设置页；服务器必须先成功返回兼容的房间查询响应，空服务器也允许建房。失败留在列表并提示。
- 设置页保留房间名称、生命、BO1/BO3、赛制和 DIY 开关。建立与加入通过明确的握手动作区分：建立拒绝重名，加入拒绝已消失的房间；旧调用方维持原有默认语义。
- 已满或正在对局的房间显示“观战”，新连接进入独立观战席。准备界面支持玩家与观战席切换；对局和 BO3 换备阶段禁止换席，观战者无需准备。最多两名玩家及 32 名观战者。
- 来源标记依据主机类型显示“局域网”或“服务器”，与搜索方式无关。同一服务实例不会因两种搜索重复显示。

## 网络接口

- 游戏传输继续使用现有 UDP 端口。房间列表使用同数字 TCP 端口；部署新版专用服务器时须同时开放这两个协议的端口。
- 局域网通过 UDP 47777 广播询问，响应包含随机查询标记和游戏端口，客户端随后通过 TCP 读取列表。列表协议 `MTGB-ROOMS/1`，只暴露房间基本信息，不包含牌组或重连凭据。
- 请求和响应有长度限制、超时和并发限制。服务器在主线程生成注册表快照，异步网络 I/O 不直接读取 Unity 对局状态。关闭服务释放查询监听器。
- 旧服务器没有目录接口，刷新和服务器建房预检会提示无法连接，需更新服务器程序。

## 验证

`RoomBrowserValidation.Run()` 在 Main Play Mode 下验证：独立页面、错误地址阻止建房、真实本机 LAN 建房、UDP 发现、TCP 只读查询且席位仍为一人、列表去重、空服务器、连接校验后进入设置。测试使用隔离的 browser-validation 配置和 18777–18779 端口。

截图 `.tools/room-browser/browser.png` 的远程房间为目录测试夹具；LAN 创建与发现使用真实 OnlineMatchService。未声称已完成两台物理机器、防火墙配置或公网部署验收。

## 观战隔离与验证

- 游戏协议升级为 v15（含先后攻选择及分席位结算视图），客户端与服务器需同步更新。
- 席位 1/2 为玩家，3–34 为观战身份；服务器拦截观战者的牌组、准备和对局操作，观战同步不会阻塞玩家。
- 初次进入、实时更新、断线恢复均使用服务器端 `OnlineSpectatorView`，清除双方手牌、输入请求、私有可用牌区域及面朝下卡牌身份。只保留公开战场、堆叠、墓地、数量和局面信息；完整对局录像仅发送给参赛玩家。
- `SpectatorValidation.Run()` 使用同一 Editor 进程中的真实 UDP 服务及四个 NGO 客户端，验证换席、观战不能准备、含观战者开局、中途加入、伪造操作拒绝、实时更新、列表分别统计玩家/观战者、结束不发送全信息录像。报告：`.tools/room-browser/spectator-result.txt`。
- `RoomBrowserValidation.Run()` 增加本机房主切换观战与返回玩家席，以及三页配色截图。验证范围仍为本机，不代表跨机器或公网部署测试。

## 列表状态与进入性能

- 每个房间从服务器配置读取 `allowCustomContent`，独立显示“DIY 允许／DIY 禁用”。
- 刷新时中央持久状态控件显示“正在搜索房间…”，完成且无结果才显示“暂无房间”；搜索提示不再放在底部。动态标签创建时立即绑定字体偏好，避免半秒后的全局扫描造成字号跳变。
- 换备卡牌网格只在局间换备阶段生成，浏览房间或准备时不读取整库、加载卡图和创建隐藏卡牌。
- 本机单次进入测量：修改前 294.2 ms、隐藏换备卡牌对象 111 个；修改后 76.4 ms、0 个。这是当前 Editor 环境的页面创建耗时，非网络搜索耗时或跨设备基准。
- `RoomBrowserValidation` 新增真实主机 DIY 字段、两种 DIY 标记、中央搜索状态、字号和对象复用、无隐藏换备卡牌检查，均通过。

## 连接恢复、换备与先后攻

- 初次连接直到成功进入房间有 6 秒总期限；主机消失、服务器不可达或入房无回应时关闭连接，恢复列表操作并显示原因。
- 房间页面使用中性深灰背景；换备隐藏全局标题、在线徽标、重复换备标题和底部说明。仅保留局数，不在房间和换备显示输赢；第一排从顶部开始，准备状态更新不再重建卡牌网格。
- BO3 双方换备准备后自动推进，无需房主再次开始。第一局随机选出先后攻选择方；后续由上一局败者选择，平局保留上次选择方。
- 服务器在选择完成后才创建 Forge 对局，因此选择时尚未生成起手牌。非选择方、观战者不能代选；取消准备会撤销待选状态。
- `MatchPreparationValidation.Run()` 使用真实本机 UDP 服务和客户端，覆盖失效主机超时恢复、不存在房间拒绝、BO3 选择权限、选择前无手牌、所选先手首先调度、双方准备自动推进、败者选择、取消后重选和第二局启动。结束第一局使用测试结果注入，不替代完整 BO3 实战验收。
- 截图 `.tools/room-browser/sideboard-revised.png` 为实际 UI 加载现有牌组的换备夹具，`.tools/room-browser/play-draw-choice.png` 为先后攻选择。

## 战场结算与只读查看

- 正常结束、中止时保留战场；中央显示获胜玩家或平局。继续查看收起结算框，设置旁才显示“离开房间”；点击该按钮收起按钮并重新打开结算框，可再次继续查看。顶部不再显示横栏。玩家手动前往换备、返回房间或离开。
- 未开启自动保存时在结算框选择保存或不保存；开启时接收完自动保存。保存动作不离开战场；接收失败或超时不会无限阻塞离开。
- Forge 结束消息附最终分席位视图，按原始席位保留败者；仅本人视图含自己的手牌和剩余牌库，公开墓地与放逐区保留可公开内容，面朝下身份仍隐藏。服务器逐个收件人发送本人的牌组；观战者没有任何人的手牌、牌库或牌组。
- 继续查看时点击本人牌库，复用找牌窗口的自适应卡图列表与分页查看剩余牌库；双方墓地、放逐区以及战场卡牌均可查看。操作请求已关闭，不能继续出牌、支付或改变最终局面。
- `EndReviewValidation.Run()`：真实本机房主、对手及观战客户端，实际向 Forge 认输，验证停留战场、最终双方数据、己方手牌/牌库/牌组、对手和观战者隐私、手动保存录像与手动进入换备。`AutomaticCase=true` 覆盖 BO1 自动保存与主动离开。截图和报告位于 `.tools/room-browser/end-*`。这是本机集成验证，非跨机器验收。
