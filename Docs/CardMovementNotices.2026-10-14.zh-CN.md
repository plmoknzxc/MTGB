# 不阻塞对局的卡牌展示／移区通知

## 最终行为

- 原生展示回调保存该接收者有权看到的卡牌，不再发布 `RevealCards` 确认输入或等待对手回复。选择卡牌的原生输入仍照常保留，没有代替玩家选择。
- 通知展示搜进手牌、磨入坟墓场、放逐等实际移区对象；不重复展示从堆叠离开的咒语，或循环等通过堆叠展示的费用来源。法术力异能不使用堆叠，其实际移区来源仍保留通知。
- 窗口写明来源费用／效果、起点和终点，显示相应卡牌。搜寻通常先移入手牌再展示，因此桥接记录准确的移区起点，避免把来源误写成已经到达的手牌。
- 多个窗口可共存、拖动标题栏；只保留右上角 X，没有确认按钮。关闭只操作本地窗口，同一通知不会在下次快照重新打开。标题栏／边框有不同颜色，另有独立阴影；单张卡图居中并放大。
- 新付款提示和所有通知窗口都接入“查看战场”，恢复时保留拖动位置和选择状态。
- 普通私有抓牌不产生对手手牌展示。公开可见性和座位记忆沿用原生及已有记忆；私有展示不会发送到其他座位或变成公共通知，盖牌保持盖牌。

## 证据

旧运行类在原生 Generous Ent 循环树林流程停到座位 2 的 `RevealCards`，保存于 `.tools/card-notices-1014/baseline-result.json`。首次改动虽解除等待，却未正确记录“先移区、后展示”的手牌通知；原 FAIL 与后续补齐结果都保留。

当前 5 个实际原生流程通过：

| 场景 | 实际结果与通知检查 |
| --- | --- |
| 循环树林 | 树林加入手牌后恢复优先权，零展示确认回复；通知只含树林，标注牌库 → 手牌和循环来源 |
| Tome Scour | 原生磨入 5 张牌，通知保留准确 5 个对象及牌库 → 坟墓场；咒语来源不重复弹窗 |
| Swords to Plowshares | 目标灰棕熊实际放逐，拥有者获得 2 点生命；通知为战场 → 放逐区 |
| Divination | 原生抓 2 张牌，对手没有手牌展示通知；咒语来源不重复弹窗 |
| Lotus Petal | 法术力异能没有进堆叠，原生牺牲后产生 1 法术力；通知保留莲花瓣的战场 → 坟墓场，避免过度排除来源 |

前四例有界输出：`.tools/card-notices-1014/native-result-1791955175852930600.json`。后续显式展示的堆叠来源过滤在适配器边界检查中验证，不算效果场景；原四例的实际展示卡处于手牌，未被该附加过滤影响。第五例单独保留补测身份，由 `audit.json` 引用原文件；未重跑前四例。

4 个适配器边界在真实初始化的 Forge 宿主检查：私有原生 GUI 展示只进入接收者通知、保持已有 pending 对象不变；已在堆叠的展示对象不重复通知；临时 GUI 的通知路由到其接收客户端座位，仍不发送到另一座位。此最后一项是接收路由检查，不是整局控制权效果证明。`boundary.json` 的 `noPendingInput` 表示未建立新的展示确认输入，不表示宿主完全没有已有 pending 对象。

39 项 Unity 检查通过，含默认／1.3 倍字号、准确来源／起终点／卡图、拖动及位置保留、实际 X 射线、关闭不重开、不发送游戏回复、多窗口与不同边框／独立阴影、查看战场隐藏／恢复付款提示及窗口、重置清理。多窗口截图合并两个独立原生结果，通知 ID 作布局适配，不能当成同一局的规则证明。截图 `movable-notices.png` 已实际复核。
