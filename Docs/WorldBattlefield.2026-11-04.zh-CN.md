# IntegratedBattlefield 网格卡牌改造

范围：按用户要求直接修改 `Assets/Scenes/IntegratedBattlefield.unity`，没有复制第三个场景。该版本允许直接打开立体战场。主菜单和构建入口当时仍使用平面战场；本批没有发布、覆盖安装或改服务器。

## 实现边界

- `BattlefieldWorldTable` 管理透视桌面相机和正交 HUD 相机。HUD 维持原屏幕坐标合同；实际桌面卡牌是独立 MeshRenderer、纸边网格、碰撞体和三维 TextMeshPro。
- 保留不可见的 RectTransform 操作锚点，复用原始 native 选项身份、拖动、攻击／阻挡、详情和分组展开回调。锚点不生成 Image 卡面，也没有给每张牌挂 World Space Canvas。
- 战场、手牌接入网格显示；移区飞行使用相同网格后端。徽记、地城与延迟效果按后续反馈恢复专用 HUD 形状、时钟与状态显示。卡面沿用已有可见性／复制牌／背面卡图查询；不会依据对手牌数猜身份。
- 详情、堆叠列表缩略图、列表选牌和其他 HUD 仍是界面控件。本批不改 Forge 规则、请求协议或网络同步。
- 横置转为桌面上的 90 度旋转，加入平滑转向、纸边、落影和分组后层。按后续反馈，双方手牌网格始终由正交相机正面显示，不随桌面倾斜；悬停提升到 34 层，位于堆叠之上、决策窗口 35 层之下。
- 动态费用沿用已有卡面／历险／双面费用来源和原始费用覆盖采样；改费时悬停显示原始印刷费用。网格状态文字与实际费用单独绘制。
- 密集场面读取现有视口范围，网格裁切和点击裁切使用同一屏幕区域。手牌由独立相机绘制，避免密集地牌穿过手牌。

## 本轮发现与修正

1. 旧 hand navigation 在直接选牌时提升到 35 层，最初挡住了网格牌点击。网格射线继承锚点祖先 Canvas 的选牌层级；重复原生视图回归通过。
2. 同帧销毁的操作锚点会在下一帧网格同步之前留下旧命中项；射线检查锚点存活和活动状态。
3. 旧 Canvas 手牌底板遮住了桌面相机的手牌；世界场景中底板改为透明命中区，保留区域标签。
4. 初始测试把三维 TextMeshPro 继承 Graphic 误判成 uGUI 卡面。检查实际 MeshRenderer／Canvas 归属后修正断言，保留 `mesh-first-failure.txt`。不是放宽为允许 TextMeshProUGUI。
5. 密集地牌和手牌共用高度会让地牌穿出手牌；改为独立手牌高度，同时从同一屏幕射线反投影，保持点击中心一致。
6. 网格手牌的高度顺序跟随既有 LeftOnTop 命中规则，并随布局更新；悬停牌高于正在回落的牌。最终调整后重新通过连续选牌／收放与网格展示检查。

## 结论限制
