# MTGB 当前开发待办

更新日期：2026-09-12。目标：MTGA 式对局体验，以及玩家通过独立 Data Editor、卡图和 Lua 制作并联机使用 DIY 卡的能力。

本清单按最近讨论整理；初始分析依据见 [产品评估](ProductReadiness.zh-CN.md)。第一阶段已实施并通过自动验证，详见 [制卡基础验收](AuthoringFoundation.zh-CN.md)。第四阶段的约定规则核心范围已验收，详见 [复杂规则验收](ComplexRulesCoverage.zh-CN.md)；第二、三阶段及后续事项仍未完成。

## 已确定的方向

- 同时加载多个数据库是正常使用方式，官方内容也可以每个系列扩展包一个库。
- 卡牌内容分类由 Data Editor 定义并保存到数据中，游戏据此搜索、筛选和限制房间可用内容；不能依据数据库文件名判定是否 DIY。
- 常见卡牌效果应有易用模板，复杂效果应通过通用 Lua 接口组合，不要求作者修改卡牌专用 C#。
- 作者在外部分发内容，玩家和权威服务器安装一致内容进行对局。
- 压缩包支持、内部目录布局和是否保留系列子目录暂缓决定。

## 暂缓决定：内容分发与目录结构

- [ ] 手动解压使用、直接识别 ZIP，或两者兼容。
- [ ] 若支持 ZIP，采用直接读取还是自动解压缓存。
- [ ] 一个包一个系列或允许多个系列；数据库、Lua、卡图在包内如何排列。
- [ ] 卡图与 Lua 是否保留系列子目录，以及包信息文件是否需要、包含哪些字段。

不将上面任何候选方案视为用户已批准的实现。无论选择哪种包装，多库、卡牌身份与数据分类需求均保留。

## 首个产品里程碑

一位不参与引擎开发的作者能够制作一个代表性 DIY 扩展包；另一位玩家与服务器安装相同内容后，双方在完整战场中完成对局。制卡过程只增加数据、卡图和 Lua 等内容，不修改卡牌专用 C#。分发文件形式在待定事项确定后补入验收标准。
